# 知乎回答：为什么我觉得 agent 开发这个工作怪怪的？等模型进化好了这个工作不就消失了？

> **原问题**：为什么我觉得 agent 开发这个工作怪怪的？agent 这个岗位就是在做模型目前做不到的事情，去完善他，那等模型进化好了，还有他什么事？这个工作不就消失了？

---

### 💡 知乎回答正文草稿

你之所以觉得怪怪的，是因为把 **Skill（提示词补丁）** 和 **Agent（运行外壳与手脚）** 混为一谈了。

前两年很多所谓的“Agent 开发”，本质上是在给大模型补脑短板：比如写几千字 Prompt 教它输出正确的 JSON，或者写规避格式错误的正则。这种针对模型智力缺陷写的 Skill 和 Patch，随着模型变聪明（从 GPT-3.5 到 Claude 3.5 / o1），确实一夜之间全作废了。

但真正的 Agent 开发，重点从来不是替模型补脑，而是替它装手和脚。

---

### 一、 模型再聪明，也替不了“手和脚”

大模型本质上是一个运行在机房里的预测器。就算未来模型的智商到了 2000，它自己也做不了这几件事：

- **真实的副作用**：模型知道怎么写代码、怎么调接口，但它没法自己运行 `git commit`，也没法替你部署服务器。必须有 Agent 在本地或云端拦截它的意图，在真实系统里落地。
- **和糟糕的环境打交道**：现实中的 API 会超时、会限流（429）、密钥会失效。这些网络抖动和环境报错，模型不可能自己写重试逻辑去兜底。
- **状态与资源管控**：当一个任务跑上几百轮，上下文爆到 10 万 Token 时，怎么做历史压缩？怎么管控几十个工具说明带来的 Token 开销？这些是系统工程，模型权重自己解决不了。

模型越聪明，它作为大脑的判断就越准。而负责连接这个大脑和真实系统的 Agent 框架与基础设施，反而要承载更长、更复杂的无人值守任务。

---

### 二、 抓底层日志看分工

如果想直观分清“模型能力”和“Agent 工程”的界限，拿代理抓包工具看一次原始日志最清楚。

我们平时调试时，把 Agent 的请求挂在开源的 **VMR (Virtual Model Router)** 上，把每一轮和模型交互的原始字节记录下来。

抓包看一眼就能分明白：

- **属于模型的（大脑）**：理解上下文、选哪个工具、生成具体代码。
- **属于 Agent 和路由层的（手脚与防护）**：
  - 把模型的 `tool_call` 转化为真实的文件读写或 API 执行；
  - 遇到合规拦截导致的 HTTP 200 空回复，在代理层无缝切到备用节点，防止 Agent 卡死；
  - 锁住 Prompt Cache 的前缀亲和，避免随机路由导致账单翻倍。

这些关于状态维持、异常兜底和物理接口交互的工程问题，就算模型演进到 GPT-6，也必须有 Agent 这一层来承载。

---

### 总结

会淘汰的不是 Agent 开发，而是那些只会写 Prompt 补丁的包装工。

模型变聪明是好事，开发者终于不用再去折腾复杂的格式教化，可以专注于真正的 Agent 工程：怎么在一个混乱、不确定的真实系统里，给聪明的模型搭一套稳定可靠的运行环境。
