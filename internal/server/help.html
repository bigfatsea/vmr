Anthropic Messages Protocol anthropic-messages

Agents that natively speak the Anthropic Messages API. Point the base URL at VMR's Anthropic-compatible endpoint; the key is sent via the x-api-key header.

Claude Code anthropic-messages

Anthropic's official terminal coding agent. Route through VMR using environment variables or ~/.claude/settings.json. Claude Code automatically connects to ANTHROPIC_BASE_URL. Tune reasoning budget with MAX_THINKING_TOKENS (fixed budget) or CLAUDE_CODE_EFFORT_LEVEL / /effort (adaptive reasoning). Official Docs →

~/.bashrc, ~/.zshrc, or shell profile (environment variables)
# Option 1: Shell Environment Variables
export ANTHROPIC_BASE_URL={{BASE_URL_ANTHROPIC}}
export ANTHROPIC_AUTH_TOKEN=YOUR_VMR_API_KEY
export ANTHROPIC_MODEL=claude

# Reasoning budget: token budget (e.g. 8192, 0 disables) or effort level (low, medium, high, max)
export MAX_THINKING_TOKENS=32768
export CLAUDE_CODE_EFFORT_LEVEL=high
~/.claude/settings.json
{
  "env": {
    "ANTHROPIC_BASE_URL": "{{BASE_URL_ANTHROPIC}}",
    "ANTHROPIC_AUTH_TOKEN": "YOUR_VMR_API_KEY",
    "MAX_THINKING_TOKENS": "32768"
  },
  "model": "claude"
}

Pi Agent openai-completions anthropic-messages

Pi is a minimalist, extensible terminal AI coding agent (earendil-works/pi-mono). Add VMR as a custom provider in ~/.pi/agent/models.json, specifying contextWindow, maxTokens, input (modalities), and reasoning flags. Pi keys providers by API protocol, so VMR appears as vmr-openai and/or vmr-anthropic — both openai-completions and anthropic-messages are supported. Official Docs →

~/.pi/agent/models.json (create if not exists)
{
  "providers": {
    "vmr": {
      "baseUrl": "{{BASE_URL_OPENAI}}",
      "api": "openai-completions",
      "apiKey": "YOUR_VMR_API_KEY",
      "models": [
        {
          "id": "coding",
          "name": "Coding (VMR)",
          "contextWindow": 200000,
          "maxTokens": 65536,
          "input": ["text", "image"],
          "reasoning": false
        },
        {
          "id": "agent",
          "name": "Agent Reasoning (VMR)",
          "contextWindow": 200000,
          "maxTokens": 65536,
          "input": ["text", "image"],
          "reasoning": true
        }
      ]
    }
  }
}

Virtual model names, context windows and token budgets in this block are refreshed from the live /status model list once it is readable — one provider entry per protocol VMR actually serves.

Codex CLI openai-completions

OpenAI's official terminal coding agent. Route through VMR via environment variables or ~/.codex/config.toml. Configure model_reasoning_effort (minimal / low / medium / high / xhigh) and model_context_window in config.toml to manage memory and thinking depth. Official Docs →

~/.bashrc, ~/.zshrc, or shell profile (environment variables)
# Option 1: Environment variables
export OPENAI_BASE_URL={{BASE_URL_OPENAI}}
export OPENAI_API_KEY=YOUR_VMR_API_KEY
~/.codex/config.toml
# Model and reasoning defaults
model = "coding"
model_reasoning_effort = "high"
model_context_window = 200000
model_auto_compact_token_limit = 180000

# VMR custom provider
[model_providers.vmr]
name = "VMR"
base_url = "{{BASE_URL_OPENAI}}"
env_key = "OPENAI_API_KEY"
wire_api = "responses"

Aider openai-completions

AI pair programming in the terminal. Route LLM requests to VMR via environment variables or ~/.aider.conf.yml. Declare custom context window limits and vision capabilities in .aider.model.metadata.json, and tune reasoning with --reasoning-effort or --thinking-tokens. Official Docs →

~/.bashrc, ~/.zshrc, or shell profile (environment variables)
# Option 1: Environment variables
export AIDER_OPENAI_API_BASE={{BASE_URL_OPENAI}}
export AIDER_OPENAI_API_KEY=YOUR_VMR_API_KEY
export AIDER_MODEL=openai/coding

# Optional: Reasoning depth and thinking budget
export AIDER_REASONING_EFFORT=high
export AIDER_THINKING_TOKENS=32768
~/.aider.conf.yml
openai-api-base: {{BASE_URL_OPENAI}}
openai-api-key: YOUR_VMR_API_KEY
model: openai/coding
edit-format: diff
weak-model: openai/coding
reasoning-effort: high
.aider.model.metadata.json — context & vision metadata
{
  "openai/coding": {
    "max_input_tokens": 200000,
    "max_output_tokens": 65536,
    "input_cost_per_token": 0,
    "output_cost_per_token": 0,
    "supports_images": true
  }
}

Continue.dev openai-completions

An open-source AI code assistant for IDEs (VS Code, JetBrains). Add VMR as a model provider in ~/.continue/config.yaml (modern format) or ~/.continue/config.json, declaring contextLength, maxTokens, and capabilities (tool_use, image_input). Official Docs →

~/.continue/config.yaml (modern format)
models:
  - name: VMR Coding
    provider: openai
    model: coding
    apiBase: {{BASE_URL_OPENAI}}
    apiKey: YOUR_VMR_API_KEY
    capabilities:
      - tool_use
      - image_input
    defaultCompletionOptions:
      contextLength: 200000
      maxTokens: 65536
      reasoningEffort: high
~/.continue/config.json (legacy format)
{
  "models": [
    {
      "title": "VMR Coding",
      "provider": "openai",
      "model": "coding",
      "apiBase": "{{BASE_URL_OPENAI}}",
      "apiKey": "YOUR_VMR_API_KEY",
      "contextLength": 200000,
      "completionOptions": {
        "maxTokens": 65536
      },
      "capabilities": ["tools", "uploadImage"]
    }
  ]
}

OpenAI Responses Protocol openai-responses

Applications and SDKs calling the next-generation OpenAI Responses API (/v1/responses). Virtual models configured under the openai-responses protocol handle downstream translation and streaming.

OpenAI Responses SDK openai-responses

Connect tools and SDKs that communicate via OpenAI's /v1/responses endpoint. Virtual models configured under the openai-responses protocol in VMR will handle downstream translation and streaming.

Python (OpenAI SDK)
from openai import OpenAI

client = OpenAI(
    base_url="{{BASE_URL_OPENAI}}",
    api_key="YOUR_VMR_API_KEY",
)

# Calls POST {{BASE_URL_OPENAI}}/responses
response = client.responses.create(
    model="coding",
    input="Analyze and refactor the auth middleware in internal/server/auth.go",
)
print(response.output_text)
Troubleshooting

• 401 from every request → the key in Authorization: Bearer must match an entry of api_keys:.

• Unknown model → virtual models are per-protocol; check Overview → Virtual Models & Endpoint Topology for the protocol each name answers on.

• 401s appearing mid-session → vmr was reloaded with a changed api_keys:; re-set the key (🔑 button, stored in this browser only).

• A request feels slow or hangs → open Overview → Live Requests: a red stalled badge means no upstream byte for over 10s; a long queued elapsed means the concurrency gate is full.

• All requests suddenly fail over → check endpoint health for cooldowns, and Quota Budgets for a saturated gate.

• A request just failed and you want to know why → Overview → Recent Failures lists the last failures with the router's own error class; the class chips double as a filter when one class floods the buffer.
