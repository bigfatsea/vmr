📖 Agent Configuration Guides

Each guide below shows how to configure a specific AI coding agent to point at this VMR instance. Three values are always needed: the Base URL (shown above), the API Key (from your admin), and a Virtual Model Name (one of the models listed above). Most agents support either the OpenAI Chat Completions protocol or the Anthropic Messages protocol — pick the protocol section that matches your agent's native API.

Anthropic Messages Protocol anthropic-messages

Agents that natively speak the Anthropic Messages API. Configure the base URL to point at VMR's Anthropic-compatible endpoint. The API key is sent via the x-api-key header.

Claude Code

anthropic-messages env var

Anthropic's official terminal coding agent. Set environment variables to route through VMR. Claude Code automatically detects ANTHROPIC_BASE_URL and uses it for all API calls. Official Docs →

📄 ~/.bashrc, ~/.zshrc, or prefix before claude
Shell 
# Point Claude Code at VMR
export ANTHROPIC_BASE_URL={{BASE_URL_ANTHROPIC}}
export ANTHROPIC_AUTH_TOKEN=YOUR_VMR_API_KEY

# Start Claude Code (model: use one of the anthropic-protocol models above)
claude --model claude

OpenAI Completions Protocol openai-completions

Agents that natively speak the OpenAI Chat Completions API. Configure the base URL to point at VMR's OpenAI-compatible endpoint. The API key is sent via the Authorization: Bearer header.

Pi Agent

openai-completions models.json

Pi is a terminal AI coding agent with multi-model support. Add VMR as a custom provider in ~/.pi/agent/models.json, then select models with /model or the --provider/--model flags. Official Docs →

📄 ~/.pi/agent/models.json (create if not exists)
JSON 
{
  "providers": {
    "vmr": {
      "baseUrl": "{{BASE_URL_OPENAI}}",
      "api": "openai-completions",
      "apiKey": "YOUR_VMR_API_KEY",
      "models": [
        { "id": "coding" },
        { "id": "agent" }
      ]
    }
  }
}

Then run pi --provider vmr --model coding, or use /model inside pi to select interactively.

Codex CLI

openai-completions env var

OpenAI's official terminal coding agent. Set OPENAI_BASE_URL to route through VMR. Official Docs →

📄 Environment variables
Shell 
# Point Codex CLI at VMR
export OPENAI_BASE_URL={{BASE_URL_OPENAI}}
export OPENAI_API_KEY=YOUR_VMR_API_KEY

# Start Codex (model: use one of the openai-protocol models above)
codex --model coding

Aider

openai-completions env var config

AI pair programming in the terminal. Supports OpenAI-compatible API via environment variables or ~/.aider.conf.yml. Official Docs →

📄 Environment variables, or ~/.aider.conf.yml
Shell 
# Option 1: Environment variables
export AIDER_OPENAI_API_BASE={{BASE_URL_OPENAI}}
export AIDER_OPENAI_API_KEY=YOUR_VMR_API_KEY
export AIDER_OPENAI_MODEL=coding
aider

# Option 2: ~/.aider.conf.yml
openai-api-base: {{BASE_URL_OPENAI}}
openai-api-key: YOUR_VMR_API_KEY
model: coding

OpenCode

openai-completions config

A terminal-based AI coding agent (opencode.ai). Configure a custom provider via opencode.json in your project or ~/.config/opencode/opencode.json. Official Docs →

📄 opencode.json (project root) or ~/.config/opencode/opencode.json
JSON 
{
  "provider": {
    "vmr": {
      "name": "VMR",
      "options": {
        "baseURL": "{{BASE_URL_OPENAI}}",
        "apiKey": "YOUR_VMR_API_KEY"
      },
      "models": {
        "coding": { "name": "Coding" }
      }
    }
  }
}

OpenClaw

openai-completions env var config

An open-source, Claude Code-compatible terminal agent. Supports OpenAI-compatible API endpoints. Configure via environment variables or a config.yaml file. Official Docs →

📄 Environment variables, or ~/.openclaw/config.yaml
Shell 
# Option 1: Environment variables
export OPENCLAW_BASE_URL={{BASE_URL_OPENAI}}
export OPENCLAW_API_KEY=YOUR_VMR_API_KEY
export OPENCLAW_MODEL=coding
openclaw

# Option 2: ~/.openclaw/config.yaml
base_url: {{BASE_URL_OPENAI}}
api_key: YOUR_VMR_API_KEY
model: coding

WorkBuddy

openai-completions config

A terminal-based AI coding assistant. Configure via ~/.workbuddy/config.yaml or .workbuddy.yaml in your project. Supports OpenAI-compatible API endpoints. Official Docs →

📄 ~/.workbuddy/config.yaml or .workbuddy.yaml
YAML 
# ~/.workbuddy/config.yaml
llm:
  provider: openai
  base_url: {{BASE_URL_OPENAI}}
  api_key: YOUR_VMR_API_KEY
  model: coding

Continue.dev

openai-completions config

An open-source AI code assistant for IDEs (VS Code, JetBrains). Add VMR as a model provider in ~/.continue/config.json. Official Docs →

📄 ~/.continue/config.json
JSON 
{
  "models": [
    {
      "title": "VMR",
      "provider": "openai",
      "model": "coding",
      "apiBase": "{{BASE_URL_OPENAI}}",
      "apiKey": "YOUR_VMR_API_KEY"
    }
  ]
}

OpenAI Responses Protocol openai-responses

Agents using the newer OpenAI Responses API. Configure the same base URL as the OpenAI Completions protocol, but use an openai-responses-protocol virtual model.

Cursor CLI Mode

responses env var

Cursor's terminal agent mode. Supports custom API endpoints via environment variables. Note: Cursor's IDE mode uses its own internal provider and cannot be redirected to VMR. Official Docs →

📄 Environment variables
Shell 
# Point Cursor CLI at VMR
export CURSOR_API_BASE={{BASE_URL_OPENAI}}
export CURSOR_API_KEY=YOUR_VMR_API_KEY

# Start Cursor CLI agent mode
cursor --model responses-model
