📖 Agent 配置指南

下面的每个指南展示了如何把某个 AI 编程 Agent 配置为指向本 VMR 实例。 始终需要三个核心值：Base URL（见上方）、API 密钥（向管理员索取）、 以及一个 虚拟模型名（即上面列出的模型之一）。 若 Agent 支持，还可进一步配置上下文窗口（如 200k）、思考/推理深度（如 medium、budget_tokens）以及视觉多模态能力（image），以完全释放 VMR 上游端点的全量能力。 大多数 Agent 支持 OpenAI Chat Completions 协议或 Anthropic Messages 协议 — 选择与你所用 Agent 原生 API 匹配的协议分区。

Anthropic Messages 协议 anthropic-messages

原生使用 Anthropic Messages API 的 Agent。将 Base URL 指向 VMR 的 Anthropic 兼容端点。API 密钥通过 x-api-key 请求头发送。

Claude Code

anthropic-messages 环境变量 thinking

Anthropic 官方的终端编程 Agent。通过环境变量路由到 VMR。 Claude Code 会自动识别 ANTHROPIC_BASE_URL 并用于所有 API 调用。 可通过 MAX_THINKING_TOKENS 设置扩展思考/推理深度预算。 官方文档 →

📄 ~/.bashrc、~/.zshrc，或在 claude 前直接加前缀
Shell 
# 将 Claude Code 指向 VMR
export ANTHROPIC_BASE_URL={{BASE_URL_ANTHROPIC}}
export ANTHROPIC_AUTH_TOKEN=YOUR_VMR_API_KEY

# 可选：推理/深度思考模型的思考预算（Token 数；0 为禁用，例如 8192 / 16384）
export MAX_THINKING_TOKENS=8192

# 启动 Claude Code（模型：使用上方某个 anthropic-messages 模型）
claude --model claude

OpenAI Completions 协议 openai-completions

原生使用 OpenAI Chat Completions API 的 Agent。将 Base URL 指向 VMR 的 OpenAI 兼容端点。API 密钥通过 Authorization: Bearer 请求头发送。

Pi Agent

openai-completions models.json context window vision & reasoning

Pi 是一个支持多模型的终端 AI 编程 Agent。将 VMR 作为自定义提供方加入 ~/.pi/agent/models.json，并显式声明 contextWindow、input（视觉能力）和 reasoning。 官方文档 →

📄 ~/.pi/agent/models.json（如果不存在则创建）
JSON 
{
  "providers": {
    "vmr": {
      "baseUrl": "{{BASE_URL_OPENAI}}",
      "api": "openai-completions",
      "apiKey": "YOUR_VMR_API_KEY",
      "models": [
        {
          "id": "coding",
          "name": "Coding (VMR)",
          "contextWindow": 200000,
          "maxTokens": 8192,
          "input": ["text", "image"],
          "reasoning": false
        },
        {
          "id": "agent",
          "name": "Agent Reasoning (VMR)",
          "contextWindow": 200000,
          "maxTokens": 16384,
          "input": ["text", "image"],
          "reasoning": true
        }
      ]
    }
  }
}

然后运行 pi --provider vmr --model coding，或在 pi 内用 /model 交互选择。

Codex CLI

openai-completions 环境变量 reasoning effort

OpenAI 官方的终端编程 Agent。设置 OPENAI_BASE_URL 以路由到 VMR。 通过 OPENAI_REASONING_EFFORT 支持推理/思考模型的思考深度调节。 官方文档 →

📄 环境变量
Shell 
# 将 Codex CLI 指向 VMR
export OPENAI_BASE_URL={{BASE_URL_OPENAI}}
export OPENAI_API_KEY=YOUR_VMR_API_KEY

# 可选：推理/思考模型的思考深度（low, medium, high）
export OPENAI_REASONING_EFFORT=medium

# 启动 Codex（模型：使用上方某个 openai-completions 模型）
codex --model coding

Aider

openai-completions 环境变量 config model metadata

终端里的 AI 结对编程工具。支持通过环境变量或 ~/.aider.conf.yml 使用 OpenAI 兼容 API。 可结合 model-metadata-file 声明完整上下文长度与多模态视觉能力。 官方文档 →

📄 环境变量，或 ~/.aider.conf.yml
Shell 
# 方案 1：环境变量
export AIDER_OPENAI_API_BASE={{BASE_URL_OPENAI}}
export AIDER_OPENAI_API_KEY=YOUR_VMR_API_KEY
export AIDER_OPENAI_MODEL=coding
aider --edit-format diff

# 方案 2：~/.aider.conf.yml（包含编辑格式与弱模型配置）
openai-api-base: {{BASE_URL_OPENAI}}
openai-api-key: YOUR_VMR_API_KEY
model: openai/coding
edit-format: diff
weak-model: openai/coding

OpenCode

openai-completions config context window vision

一个基于终端的 AI 编程 Agent（opencode.ai）。 在 opencode.json 中配置自定义提供方，支持显式声明 contextWindow、maxTokens 和 supportsImages。 官方文档 →

📄 opencode.json（项目根目录）或 ~/.config/opencode/opencode.json
JSON 
{
  "provider": {
    "vmr": {
      "name": "VMR",
      "options": {
        "baseURL": "{{BASE_URL_OPENAI}}",
        "apiKey": "YOUR_VMR_API_KEY"
      },
      "models": {
        "coding": {
          "name": "Coding",
          "contextWindow": 200000,
          "maxTokens": 8192,
          "supportsImages": true,
          "reasoning": false
        },
        "agent": {
          "name": "Agent",
          "contextWindow": 200000,
          "maxTokens": 16384,
          "supportsImages": true,
          "reasoning": true
        }
      }
    }
  }
}

OpenClaw

openai-completions 环境变量 config thinking & vision

一个开源、兼容 Claude Code 的终端 Agent。支持 OpenAI 兼容的 API 端点。 通过环境变量或 config.yaml 配置文件配置上下文窗口、视觉能力以及思考预算。 官方文档 →

📄 环境变量，或 ~/.openclaw/config.yaml
Shell 
# 方案 1：环境变量
export OPENCLAW_BASE_URL={{BASE_URL_OPENAI}}
export OPENCLAW_API_KEY=YOUR_VMR_API_KEY
export OPENCLAW_MODEL=coding
export OPENCLAW_REASONING_EFFORT=medium
openclaw

# 方案 2：~/.openclaw/config.yaml
base_url: {{BASE_URL_OPENAI}}
api_key: YOUR_VMR_API_KEY
model: coding
context_window: 200000
max_tokens: 8192
vision: true
thinking:
  budget_tokens: 8192

WorkBuddy

openai-completions config context window vision

一个基于终端的 AI 编程助手。通过 ~/.workbuddy/config.yaml 或 项目里的 .workbuddy.yaml 配置。支持上下文长度、最大输出 Token 及多模态视觉输入。 官方文档 →

📄 ~/.workbuddy/config.yaml 或 .workbuddy.yaml
YAML 
# ~/.workbuddy/config.yaml
llm:
  provider: openai
  base_url: {{BASE_URL_OPENAI}}
  api_key: YOUR_VMR_API_KEY
  model: coding
  context_window: 200000
  max_output_tokens: 8192
  supports_vision: true
  reasoning_effort: medium

Hermes

openai-completions env var context & vision

一个快速、可扩展的终端 AI 编程 Agent。支持通过环境变量配置 OpenAI 兼容端点的上下文长度、最大输出及视觉开关。 官方文档 →

📄 环境变量
Shell 
# 将 Hermes 指向 VMR
export HERMES_BASE_URL={{BASE_URL_OPENAI}}
export HERMES_API_KEY=YOUR_VMR_API_KEY
export HERMES_MODEL=coding

# 模型参数：上下文长度、最大输出 Token、视觉支持与推理深度
export HERMES_CONTEXT_WINDOW=200000
export HERMES_MAX_OUTPUT_TOKENS=8192
export HERMES_VISION=true
export HERMES_REASONING_EFFORT=medium
hermes

OpenDesign

openai-completions config vision

一个 AI 驱动的设计转代码 Agent。通过 OpenAI 兼容 API 路由 LLM 调用。 启用视觉多模态能力以支持 UI 截图与原型识别。 官方文档 →

📄 ~/.opendesign/config.yaml
YAML 
# ~/.opendesign/config.yaml
llm:
  provider: openai
  base_url: {{BASE_URL_OPENAI}}
  api_key: YOUR_VMR_API_KEY
  model: coding
  context_tokens: 200000
  max_output_tokens: 8192
  # 视觉能力支持 UI 设计截图与设计 Token 解析
  vision: true

Continue.dev

openai-completions config context length capabilities

一个面向 IDE（VS Code、JetBrains）的开源 AI 代码助手。在 ~/.continue/config.json 中将 VMR 添加为模型提供方， 支持声明 contextLength 及模型能力 capabilities（工具调用、图片上传等）。 官方文档 →

📄 ~/.continue/config.json
JSON 
{
  "models": [
    {
      "title": "VMR Coding",
      "provider": "openai",
      "model": "coding",
      "apiBase": "{{BASE_URL_OPENAI}}",
      "apiKey": "YOUR_VMR_API_KEY",
      "contextLength": 200000,
      "maxStopWords": 8192,
      "capabilities": ["tools", "uploadImage"]
    }
  ]
}

OpenAI Responses 协议 openai-responses

使用较新 OpenAI Responses API 的 Agent。使用与 OpenAI Completions 协议相同的 Base URL， 但需使用一个 openai-responses 协议的虚拟模型。

Cursor CLI Mode

openai-responses 环境变量 reasoning effort

Cursor 的终端 Agent 模式。支持通过环境变量配置自定义 API 端点。 使用 CURSOR_REASONING_EFFORT 调节思考/推理深度。 注意：Cursor 的 IDE 模式使用自己的内部提供方，无法重定向到 VMR。 官方文档 →

📄 环境变量
Shell 
# 将 Cursor CLI 指向 VMR
export CURSOR_API_BASE={{BASE_URL_OPENAI}}
export CURSOR_API_KEY=YOUR_VMR_API_KEY

# 可选：推理/思考模型的思考深度（low / medium / high）
export CURSOR_REASONING_EFFORT=medium

# 启动 Cursor CLI Agent 模式
cursor --model responses-model
