# Changelog

All notable changes to this project are documented here, in
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format. This project
tags releases `vX.Y` rather than strict semver (see `internal/buildinfo`'s
doc comment for why there is no other version file to keep in sync) — the
version headers below match the tag with the leading `v` dropped.

`release.yml`'s release job extracts the section matching the pushed tag and
uses it verbatim as the GitHub Release body — GitHub's own auto-generated
notes (bare PR titles) are unreadable on this repo's mostly direct-to-main
workflow, so every tag needs a matching section here before it's pushed, or
the release job fails on purpose rather than publishing something empty.
See this file's row in `CLAUDE.md`'s Conventions section for the write-time
process (write into `[Unreleased]` as you go, retitle it when cutting a tag).

Sections before the most recent release are compressed summaries — the
commits and design docs hold the full reasoning.

## [Unreleased]

### Added
- live stats and in-flight request telemetry (`GET /stats`): single-binary real-time monitoring and historical rollups. `internal/livestats` provides a zero-dependency leaf ledger recording hourly slim WAL lines (`vmr-stats-YYYYMMDD-HH.jsonl`, 0600) and cumulative rollup history (`vmr-stats-rollup.jsonl`), with lazy hourly rollups, crash-safe duplicate-line last-wins absorption on startup, and in-memory ring buffers maintaining nearest-rank percentiles (p50/p90 for TTFT and per-request token throughput). It holds its own advisory `.vmr-stats.lock` on `log_dir` (independent of audit's, so `-audit=false` deployments still get single-writer protection), and with `-audit=false` the response recorder runs in status-only mode (no body buffering). `internal/router` provides an in-flight requests registry (`InflightRegistry`) tracking active requests across queueing, dispatch, and stream execution with lock-free per-chunk milestone updates (`sent_at`, `first_byte_at`, `last_byte_at`, and `est_out`). `GET /stats` exposes concurrency as `limit`/`in_flight`/`waiting`, `hourly[]` (last 48h by default, `?range=24h|3d|7d` widens the tail; 7d cap deliberate) / `daily[]` (local-calendar-day) rollups, per-provider rows with `last_10`/`last_100` window blocks (actual sample count, window token sums, TTFT and `toks` p50/p90 — `toks` is the one throughput caliber: four-component token sum over total duration, stream and non-stream alike; `tps_*` was retired before ever shipping), an `overall` merged window block (percentiles cannot be merged client-side, the server computes it over all rings' sample union), a `recent_errors[]` ring of the last 50 failed/canceled requests stamped with the routing half's own `error_class`, and usage grouped by independent `client_key_tag` and upstream `key_label` dimensions. Its historical aggregate is read-cached briefly (keyed per range) so several dashboards polling at once cost one aggregation, while concurrency and in-flight are computed fresh on every read. The rollup file is an append-only archive; the in-memory image (and every `by_*` total) is a ~7-day sliding window (7 whole calendar days plus today), so `/stats` cost stays constant regardless of deployment age and deeper history is `vmr analyze`'s job. Only requests that reached a virtual model are booked — pre-probe failures (401, invalid JSON) are not. Token `in` throughout is fresh input (cache-read/cache-write excluded). The built-in dashboard is the unified console's Overview page (next entry) — there is no separate `/stats.html` page
- the unified built-in console (per the console-unification design): one shared `console.css`/`console.js` pair (`go:embed`, injected into each page once at startup — the single source for design tokens, components, number formatting, and the `VMRAuth` key flow: one modal, 401 → prompt → save → auto-retry, shared `localStorage` key across all pages). `/status.html` is the **Overview page** — the former status and stats dashboards merged into one flat page: vitals strip (concurrency / requests / tokens / endpoint health) with a one-line system status, quota budgets, virtual-model topology with unified fallback endpoints (per-endpoint quota headroom via a read-side join against the existing quota exports, and a 24h traffic-share column folded client-side from `hourly[]`), live in-flight requests, recent failures with error-class filter chips, performance with last-10/last-100 whole-row window switching, and a traffic & usage section (pure-SVG requests+tokens combo chart with error markers and hover breakdown, plus per-key usage tables) under a single 24h/3d/7d window control. The whole page refreshes on one clock (5 minutes, click to refresh now, paused — visibly — while the tab is hidden); the header alert pill carries actionable states only. `/log.html` is a full-bleed terminal on the same skeleton: level chips (presentation-only heuristic classification of the plain-text stream), substring filter with hit highlighting, copy view, ⌘P pause, auto-scroll handoff ("↓ N new" chip), and a dedicated disconnect banner with reconnect. `/help.html` is rebuilt as accordion agent-setup guides with a real-data connection card (copyable per-protocol base URLs, live model × protocol table, connection check); its `.zh` sibling is the only translated console page left. `/status` gains `alerts[]` (config issues, cooling-down endpoints, quota gates near exhaustion — rolling statistics never qualify) and per-endpoint `provider`/`key_label`/`model`/`from_fallback`/`headroom` fields (headroom omitted for unmetered accounts). Audit forwarded attempts are stamped with `tokens` (four raw components, quota-parity pinned) and `key_label` (the provider's `api_keys` map label or key tail)
- unified money display: `fmtutil.FmtCurrency` (always two decimals with the currency's symbol — `$124.36` / `¥34.20` / `CAD 12.00`) is now the single formatter for every ledger amount across the macro report, journey reports, task clusters, and the dashboards; `fmtutil.FmtCurrencyPrecise` (four decimals) serves unit-rate columns (§6.6 cost per 1M out / per successful request) where sub-cent precision is the point. Previously the three surfaces disagreed on the same total (macro `1.2823 USD`, journey dropping cents at ≥100, dashboards always two decimals); the cross-language fixture now pins the currency formatters byte-identical between Go and the dashboard JS. `journeys/index.json` rows and task-cluster members gain a `currency` field so cluster cost lines are currency-labeled instead of bare numbers
- `vmr diff <coordA> <coordB>`: request-level structural comparison CLI command for comparing two audit records on header, system prompt, tools (names plus the manifest `ToolsHash`, so an identical-name toolset whose schema changed is still flagged), message sequence LCP/divergence, and an automated structural verdict
- Prompt cache break attribution: ctxgraph manifests now capture `tools_hash` (cache schema version bumped to 9); steps record structured `cache_break` attribution (`system` — including a toolset appearing or disappearing; `tools`; `provider_switch`; `history:*`; and `unexplained` — a relative drop steep enough not to be append dilution *and* a current hit ratio near zero, i.e. a real full-prefix re-encode) rendered across decision spine markdown, journey-viewer timeline badges, and both the compare `.md` and `journey-compare.html` Cache Breaks tables
- Touched artifacts tracking: journey extraction now identifies workspace files mutated or touched by structured file tools and bash command heuristics, persisted in `j-<id>.json`'s `artifacts` and rendered with step anchor jumps in journey-viewer
- Repeated task clustering: `journeys/index.json` and `index.md` group candidate journeys with similar task titles into clusters, each member carrying its dominant model / net working time / cost so the cluster marks the cheapest (`⭐`) and fastest (`⚡`) run and suggests the cheapest-vs-priciest `vmr analyze -compare`
- `-llm-addr` interpretation results now persist into the JSON products (design doc §3.6): `j-<id>.json` carries `llm_interpretation` and the compare JSON carries `llm_interpretation` + `llm_divergence`, each holding the model, duration, status, and the model's own text; the `.md`'s interpretation section(s) render from those records, so `-render-only` reproduces them from the JSON instead of scraping the previous `.md` (a failed call is recorded with `status: "failed"` and renders nothing, matching the previous degrade behavior)

- console Overview page: the Live Requests table and concurrency vitals now poll adaptively on their own fast cadence (~2s while requests are in flight or queued, backing off to 15s when idle, paused cleanly while the tab is hidden), delivering a live elapsed/stalled/tokens view without coupling to whole-page 5-minute refreshes or introducing SSE complexity. `/stats` computes in-flight and concurrency fresh on every read; the ledger fold behind the rest of the payload is read-cached for longer than the poll cadence, so a burst of polls costs one aggregation. Poller requests use direct unprompted probing to avoid modal races and function out of the box on keyless instances
- the transient cooldown curve's first step is 5s instead of 2s (still ×2 per consecutive failure, still capped at 5min — now 7 distinct steps). 2s let a recovery probe pass re-open a slow-but-alive upstream fast enough that new sessions (routed by configured order, since failover success moves the sticky pointer away) re-hit it in a tight loop, each round paying a full response_header timeout; 5s slows that flap 2.5× without making a single transient failure expensive

### Fixed
- role rewriting (`RewriteRoles`/`RewriteInputRoles`) now bounds each message element with the fuzz-tested `WalkArrayElements` primitive: a malformed region inside one element can no longer leak the scan past the element's bounds and mis-rewrite nested content — any malformed element aborts the rewrite and the body goes upstream byte-for-byte unchanged (valid bodies are spliced identically to before)
- the degraded quota estimate no longer charges an inline image's base64 bytes a second time as document tokens: attachment spans are typed by the producing field (with the source object's media_type disambiguating Anthropic's shared `"data":"` field), so `estimateDocumentTokens` counts document payloads only — image-only requests whose text merely mentions `application/pdf` also stop opening the document estimate
- `ctxgraph` edit classification: a same-length turn whose last 1–2 messages were replaced is now classified `ReplaceTail`, not `Append` — the full-prefix re-encode it causes was being reported as a spurious `unexplained` prompt-cache break in journey analysis

### Added
- dashboard amounts render in the slices' own currency: the macro amounts are already converted Go-side to the currency `-currency`/report.yaml selects, `macro/finance.json` carries that code in `pricing.currency`, and the dashboard picks the matching symbol (`$`/`¥`/`€`/`£`; an unmapped code prefixes as the code itself)
- `vmr analyze -render-only` — re-render every resident human-readable Markdown product (`vmr-report.md`, `journeys/index.md`, `journeys/benchmarks.md`, `journeys/details/j-<id>.md`, `compares/index.md` + `compare-*.md`, `requests/failed.md`) from the already-written JSON slices, skipping all log decompression/parsing/aggregation. Verifies `manifest.json` integrity first (a mismatching or missing manifest is rejected); the render language is inherited from the manifest's stored language (use a full run to switch languages). Request details and evidence are never materialized by it. It also refreshes the dashboard skeleton pages, so it can bring a self-copied dashboard up to the binary's generation
- `vmr analyze -no-cache` — resident bypass for the product-level caches (not a transition toggle): forces full recomputation for A/B comparison whenever cache behavior looks suspect. The caches themselves are transparent: an L2 product cache keyed by an ordered sha256 digest chain over input file hashes + pricing-relevant config + format version + analysis parameters skips aggregation and journey construction when nothing relevant changed, and an L3 presentation cache keyed over ViewModel fingerprints + renderer version + language skips re-rendering when neither data nor renderer changed — cold and warm runs produce byte-identical output, pinned by test
- `analytics.serve` / `analytics.serve_dir` — opt-in HTTP hosting of the analyze output directory at `/reports/*` (default off; `serve_dir` defaults to `./reports`, the same default as `analyze -o`). Security model: with no `api_keys` configured the whole `/reports/*` tree hard-rejects with 403 (it never falls back to the routing API's no-key-allow behavior); HTML skeleton pages serve unauthenticated (zero business data), all data files (`.json`/`.jsonl`/`.md`) require the Bearer key; path traversal, symlinks and directory listing are rejected
- `providers[].disabled` — a one-line temporary takedown for an upstream account (rate-limited, 5xx-ing, protocol upgrade, maintenance): set `disabled: true`, reload, and the provider is treated as nonexistent at every downstream consumer (no routes, no quota counters, absent from `/status`); flip back and reload to restore. Referencing a disabled provider from an endpoint is not an error — `vmr check` warns "disabled, carries no traffic" per reference site so the no-op is visible, and a disabled provider's missing `api_key` no longer raises the api_key-missing warning at all
- `timeouts.probe` (moved in from top-level `probe_timeout`) and a new top-level `ttl:` block gathering the three lifecycle fields: `ttl.sticky` (Go duration syntax, was `sticky_ttl`), `ttl.image_cache` (was `image_cache_ttl_days`), `ttl.audit_retention` (was `audit_retention_days`). The two long-horizon fields take an extended calendar syntax — `Nd`/`Nw`/`Nmo`/`Ny`, case-insensitive, with the same fixed-length month approximation as quota's `every: 1mo` — and the parser explicitly rejects `forever`/`permanent`/`never`: "permanent" is no longer a semantic this config expresses; users who need extreme retention write a large concrete value (`90000d` ≈ 246 years)
- `model_defaults:` — a top-level, real-model-keyed declaration block for the horizontal facts of an upstream model: `capabilities` and `max_context_tokens`, optional `providers: [...]` scoping (absent = applies on every provider), and a `"*"` wildcard fallback entry. `capabilities`/`max_context_tokens` fall back per-field and independently: virtual-model explicit declaration → exact model key → `"*"` → unconstrained. The whole block is optional; a config without it behaves as everything-unconstrained, the same semantics `core.Endpoint.HasCapability` has always promised
- `vmr check` warns when a `fallback_endpoints` protocol key matches no virtual model's endpoints, including when every model that does declare the protocol has opted out via `fallback: false` (a bucket whose sole referencing model self-excludes is exactly as dead as one no model declares at all) — the long-standing silent drop (a fallback attached to no ingress is dead config) is now surfaced as a warning, not an error, since adding a matching endpoint later is a legitimate evolution path

### Changed
- **Breaking**: `role_map` and `sticky_ttl` moved from the endpoint-group (`models.<name>.endpoints[<protocol>][]`) to the provider (`providers[]`) — the role rejection `role_map` repairs is a property of a provider's API implementation (revalidated at the gateway's own enum check, e.g. DashScope rejecting the `developer` role for every model it hosts), and prompt-cache lifetime is a property of the provider's infrastructure, so both are declared once per account and inherited by every endpoint the account backs. Migration: cut `role_map: {developer: system}` / `sticky_ttl: 2h` from individual endpoint entries and place them once under the matching provider in `providers:`; strict YAML rejects the old shape as unknown fields. Load-time validation moves with the fields: provider-level `sticky_ttl` must be positive and ≤ 24h (the sticky registry's memory-eviction backstop), and `role_map` rejects blank role names, blank targets, whitespace-padded names (matching is an exact string compare, so a padded name silently never matches or rewrites to a role the gateway rejects), and self-mappings (`system: system`) — an empty map is normalized to nil. `vmr check` prints each provider's `role_map`/`sticky_ttl` in the Providers section, and endpoint rows still show the inherited values when they differ from the global default
- **Breaking**: `soft_block_failover` configuration option (per virtual model or per endpoint) and router-level 2xx peek failover are removed. Content-flagged 2xx responses (such as MiniMax `input_sensitive`/`output_sensitive`) are passed through byte-faithfully like normal 2xx responses; `respnorm` continues to observe and record `soft_block_detected` in the audit norm trail (adjudicated in `KNOWN_ISSUES`)
- **Breaking**: `audit_retention` loses its "0 = never delete" reading — `0`/absent now means "use the default (90d)" like every other TTL field, and there is no way to spell "keep forever" anymore (write `90000d` or larger for extreme retention). A deployment that relied on the old zero-value will start deleting audit files older than 90 days at the next reload unless it sets an explicit large value
- **Breaking**: `models.<name>.endpoints` and top-level `fallback_endpoints` are keyed by ingress protocol — `endpoints: {openai-completions: [...], anthropic-messages: [...]}` — and each entry loses its per-entry `protocol:` field (strict YAML rejects the old shape as unknown fields; no compatibility layer). Same key space as `providers[].base_url`; per-entry override fields are unchanged; within a protocol bucket, entry order still decides try-order
- **Breaking**: endpoint-level `capabilities`/`max_context_tokens` overrides are removed — declare these facts once per real model in `model_defaults:` (or override at the virtual-model level, which remains the mechanism for "this virtual model deliberately downgrades a model it shares with others"). ### Changed
- Quota scoring merges rate-limit gates as **binary constraints** instead of the old `min(1, raw)` cap: a live gate (`used < amount`) no longer touches the provider's score at all — an underused billing bucket's use-it-or-lose-it boost now survives idle rate gates, which the old cap flattened to ≤ 1.0 for every gated account — and a fully consumed gate zeroes the score until the short window resets. A gate is a safety-margined local stand-in for the vendor's real rate limit, so the only signal it reliably carries is blown-or-not; the graded `raw` was a calibration artifact, not a capacity gauge (adjudicated as `KNOWN_ISSUES` 2.88). Config guidance moved with it: set a gate's `amount` slightly tighter than the vendor's real limit, with margin for calibration error and in-flight requests
- Upstream transports now enable HTTP/2 (`ForceAttemptHTTP2`): a custom `DialContext` silently disables Go's automatic h2 upgrade, so every provider connection was walking HTTP/1.1 — no multiplexing, no HPACK, and nothing anywhere recorded that fact
- Audit records now serialize with `SetEscapeHTML(false)`: bodies containing `<`, `>` or `&` (code payloads are the primary traffic) were being written as `\u003c`-style escapes, so the audit file was not the bytes the client sent and `vmr replay`'s byte-for-byte promise failed at the wire level
