# Changelog

All notable changes to this project are documented here, in
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format. This project
tags releases `vX.Y` rather than strict semver (see `internal/buildinfo`'s
doc comment for why there is no other version file to keep in sync) — the
version headers below match the tag with the leading `v` dropped.

`release.yml`'s release job extracts the section matching the pushed tag and
uses it verbatim as the GitHub Release body — GitHub's own auto-generated
notes (bare PR titles) are unreadable on this repo's mostly direct-to-main
workflow, so every tag needs a matching section here before it's pushed, or
the release job fails on purpose rather than publishing something empty.
See this file's row in `CLAUDE.md`'s Conventions section for the write-time
process (write into `[Unreleased]` as you go, retitle it when cutting a tag).

Sections before the most recent release are compressed summaries — the
commits and design docs hold the full reasoning.

## [0.7.0] - 2026-09-12

### Added
- load testing overhaul (`loadtest/`, `vmr-loadtest.sh`): comprehensive review and measurement calibration. Scenarios expanded from 12 to 17, adding `drip_stream` (~5s slow-drip SSE streaming to stress sustained concurrency, InflightRegistry, watchdog, and concurrent audit writes), `anthropic_stream` and `responses_stream` (protocol SSE streaming adapters), `quota` (metering and headroom ranking against real usage), and `sticky` (cross-request session fingerprint caching and endpoint pinning). Client-side Vegeta attacks are bucketed into three separate cost regimes (`plain`, `stream`, and `image`) to prevent long-stream and image decode latencies from distorting the routing floor. Added low-rate 2s warmup round (excluding lazy-init and initial-state noise from formal stats), background process resource sampling (RSS peak and cumulative CPU time via 500ms `ps` polling), VCS revision stamp from `debug/buildinfo`, dynamic target parsing (retiring hardcoded scenario counts), interleaved target generation for image variants (preventing scenario starvation during short rounds), target-to-audit consistency assertions (±20% tolerance, guarding against silent configuration regressions), and an executable architectural boundary test (`TestArchitecture_LoadtestRunnerNoInternalDeps`) in `internal/archtest`.
- live stats and in-flight request telemetry (`GET /stats`): single-binary real-time monitoring and historical rollups. `internal/livestats` provides a zero-dependency leaf ledger recording hourly slim WAL lines (`vmr-stats-YYYYMMDD-HH.jsonl`, 0600) and cumulative rollup history (`vmr-stats-rollup.jsonl`), with lazy hourly rollups, crash-safe duplicate-line last-wins absorption on startup, and in-memory ring buffers maintaining nearest-rank percentiles (p50/p90 for TTFT, p50/p10 for per-request token throughput — p10 because throughput is a yield metric whose worst-case tail is the bottom decile, the opposite direction from a cost metric like TTFT). It holds its own advisory `.vmr-stats.lock` on `log_dir` (independent of audit's, so `-audit=false` deployments still get single-writer protection), and with `-audit=false` the response recorder runs in status-only mode (no body buffering). `internal/router` provides an in-flight requests registry (`InflightRegistry`) tracking active requests across queueing, dispatch, and stream execution with lock-free per-chunk milestone updates (`sent_at`, `first_byte_at`, `last_byte_at`, and `est_out`). `GET /stats` exposes concurrency as `limit`/`in_flight`/`waiting`, `hourly[]` (last 48h by default, `?range=24h|3d|7d` widens the tail; 7d cap deliberate) / `daily[]` (local-calendar-day) rollups, per-provider rows with `last_10`/`last_100` window blocks (actual sample count, window token sums, TTFT p50/p90 and `toks` p50/p10 — `toks` is the one throughput caliber: output-token generation throughput, excluding the time-to-first-token wait for streamed requests and using the full duration for non-streamed ones, floored at a 50ms generation span to drop physically-implausible bursts; `tps_*` was retired before ever shipping), an `overall` merged window block (percentiles cannot be merged client-side, the server computes it over all rings' sample union), a `recent_errors[]` ring of the last 50 failed/canceled requests stamped with the routing half's own `error_class`, and usage grouped by independent `client_key_tag` and upstream `key_label` dimensions. Its historical aggregate is read-cached briefly (keyed per range) so several dashboards polling at once cost one aggregation, while concurrency and in-flight are computed fresh on every read. The rollup file is an append-only archive; the in-memory image (and every `by_*` total) is a ~7-day sliding window (7 whole calendar days plus today), so `/stats` cost stays constant regardless of deployment age and deeper history is `vmr analyze`'s job. Only requests that reached a virtual model are booked — pre-probe failures (401, invalid JSON) are not. Token `in` throughout is fresh input (cache-read/cache-write excluded). The built-in dashboard is the unified console's Overview page — there is no separate `/stats.html` page.
- the unified built-in console (per the console-unification design): one shared `console.css`/`console.js` pair (`go:embed`, injected into each page once at startup — the single source for design tokens, components, number formatting, and the `VMRAuth` key flow: one modal, 401 → prompt → save → auto-retry, shared `localStorage` key across all pages). Four pages: `/status.html` is the **Overview page** — vitals strip (concurrency / requests / tokens / endpoint health) with a one-line system status, live in-flight requests, performance with last-10/last-100 whole-row window switching, a traffic & usage section (pure-SVG requests+tokens combo chart with error markers and hover breakdown, plus per-provider/model and per-caller usage tables) under a single 24h/3d/7d window control, and recent failures with error-class filter chips at the bottom. The whole page refreshes on one clock (5 minutes, click to refresh now, paused — visibly — while the tab is hidden); Live Requests/Recent Failures/concurrency additionally poll adaptively (~2s active, 15s idle); the header alert pill carries actionable states only. `/models.html` is the **Models page** — quota budgets and virtual-model topology with unified fallback endpoints (per-endpoint quota headroom via a read-side join against the existing quota exports, and a 24h traffic-share column folded client-side from `hourly[]`), refreshed on the same 5-minute clock with no adaptive polling (both tables are relatively static configuration/topology facts). `/log.html` is a full-bleed terminal on the same skeleton: level chips (presentation-only heuristic classification of the plain-text stream), substring filter with hit highlighting, copy view, ⌘P pause, auto-scroll handoff ("↓ N new" chip), and a dedicated disconnect banner with reconnect. `/help.html` is rebuilt as accordion agent-setup guides with a real-data connection card (copyable per-protocol base URLs, live model × protocol table, connection check); its `.zh` sibling is the only translated console page left. None of the four pages render a second header row when they have no in-page anchors to navigate to. `/status` gains `alerts[]` (config issues, cooling-down endpoints, quota gates near exhaustion — rolling statistics never qualify) and per-endpoint `provider`/`key_label`/`model`/`from_fallback`/`headroom` fields (headroom omitted for unmetered accounts). Audit forwarded attempts are stamped with `tokens` (four raw components, quota-parity pinned) and `key_label` (the provider's `api_keys` map label or key tail).
- unified money display: `fmtutil.FmtCurrency` (always two decimals with the currency's symbol — `$124.36` / `¥34.20` / `CAD 12.00`) is now the single formatter for every ledger amount across the macro report, journey reports, task clusters, and the dashboards; `fmtutil.FmtCurrencyPrecise` (four decimals) serves unit-rate columns (§6.6 cost per 1M out / per successful request) where sub-cent precision is the point. The cross-language fixture pins the currency formatters byte-identical between Go and dashboard JS. `journeys/index.json` rows and task-cluster members gain a `currency` field so cluster cost lines are currency-labeled instead of bare numbers. Web dashboard amounts render in the slices' own currency (`pricing.currency` from `macro/finance.json`), displaying the matching symbol (`$`/`¥`/`€`/`£`; unmapped codes prefix as the code itself).
- `vmr diff <coordA> <coordB>`: request-level structural comparison CLI command for comparing two audit records on header, system prompt, tools (names plus the manifest `ToolsHash`, so an identical-name toolset whose schema changed is still flagged), message sequence LCP/divergence, and an automated structural verdict.
- Prompt cache break attribution: ctxgraph manifests now capture `tools_hash` (cache schema version bumped to 9); steps record structured `cache_break` attribution (`system` — including a toolset appearing or disappearing; `tools`; `provider_switch`; `history:*`; and `unexplained` — a relative drop steep enough not to be append dilution *and* a current hit ratio near zero, i.e. a real full-prefix re-encode) rendered across decision spine markdown, journey-viewer timeline badges, and both the compare `.md` and `journey-compare.html` Cache Breaks tables.
- Touched artifacts tracking: journey extraction now identifies workspace files mutated or touched by structured file tools and bash command heuristics, persisted in `j-<id>.json`'s `artifacts` and rendered with step anchor jumps in journey-viewer.
- Repeated task clustering: `journeys/index.json` and `index.md` group candidate journeys with similar task titles into clusters, each member carrying its dominant model / net working time / cost so the cluster marks the cheapest (`⭐`) and fastest (`⚡`) run and suggests the cheapest-vs-priciest `vmr analyze -compare`.
- `-llm-addr` interpretation results now persist into the JSON products (design doc §3.6): `j-<id>.json` carries `llm_interpretation` and the compare JSON carries `llm_interpretation` + `llm_divergence`, each holding the model, duration, status, and the model's own text; the `.md`'s interpretation section(s) render from those records, so `-render-only` reproduces them from the JSON instead of scraping the previous `.md` (a failed call is recorded with `status: "failed"` and renders nothing, matching the previous degrade behavior).
- `vmr analyze -render-only` — re-render every resident human-readable Markdown product (`vmr-report.md`, `journeys/index.md`, `journeys/benchmarks.md`, `journeys/details/j-<id>.md`, `compares/index.md` + `compare-*.md`, `requests/failed.md`) from the already-written JSON slices, skipping all log decompression/parsing/aggregation. Verifies `manifest.json` integrity first (a mismatching or missing manifest is rejected); the render language is inherited from the manifest's stored language (use a full run to switch languages). Request details and evidence are never materialized by it. It also refreshes the dashboard skeleton pages, bringing deployed dashboards up to the binary's generation.
- `vmr analyze -no-cache` — resident bypass for the product-level caches: forces full recomputation for A/B comparison whenever cache behavior looks suspect. The caches themselves are transparent: an L2 product cache keyed by an ordered sha256 digest chain over input file hashes + pricing-relevant config + format version + analysis parameters skips aggregation and journey construction when nothing relevant changed, and an L3 presentation cache keyed over ViewModel fingerprints + renderer version + language skips re-rendering when neither data nor renderer changed — cold and warm runs produce byte-identical output, pinned by test.
- `analytics.serve` / `analytics.serve_dir` — opt-in HTTP hosting of the analyze output directory at `/reports/*` (default off; `serve_dir` defaults to `./reports`, the same default as `analyze -o`). Security model: with no `api_keys` configured the whole `/reports/*` tree hard-rejects with 403 (it never falls back to the routing API's no-key-allow behavior); HTML skeleton pages serve unauthenticated (zero business data), all data files (`.json`/`.jsonl`/`.md`) require the Bearer key; path traversal, symlinks and directory listing are rejected.
- `providers[].disabled` — a one-line temporary takedown for an upstream account (rate-limited, 5xx-ing, protocol upgrade, maintenance): set `disabled: true`, reload, and the provider is treated as nonexistent at every downstream consumer (no routes, no quota counters, absent from `/status`); flip back and reload to restore. Referencing a disabled provider from an endpoint is not an error — `vmr check` warns "disabled, carries no traffic" per reference site so the no-op is visible, and a disabled provider's missing `api_key` no longer raises the api_key-missing warning at all.
- `timeouts.probe` (moved in from top-level `probe_timeout`) and a new top-level `ttl:` block gathering the three lifecycle fields: `ttl.sticky` (Go duration syntax, was `sticky_ttl`), `ttl.image_cache` (was `image_cache_ttl_days`), `ttl.audit_retention` (was `audit_retention_days`). The two long-horizon fields take an extended calendar syntax — `Nd`/`Nw`/`Nmo`/`Ny`, case-insensitive, with the same fixed-length month approximation as quota's `every: 1mo` — and the parser explicitly rejects `forever`/`permanent`/`never`: "permanent" is no longer a semantic this config expresses; users who need extreme retention write a large concrete value (`90000d` ≈ 246 years).
- `model_defaults:` — a top-level, real-model-keyed declaration block for the horizontal facts of an upstream model: `capabilities` and `max_context_tokens`, optional `providers: [...]` scoping (absent = applies on every provider), and a `"*"` wildcard fallback entry. `capabilities`/`max_context_tokens` fall back per-field and independently: virtual-model explicit declaration → exact model key → `"*"` → unconstrained. The whole block is optional; a config without it behaves as everything-unconstrained, the same semantics `core.Endpoint.HasCapability` has always promised.
- `vmr check` warns when a `fallback_endpoints` protocol key matches no virtual model's endpoints, including when every model that does declare the protocol has opted out via `fallback: false` (a bucket whose sole referencing model self-excludes is exactly as dead as one no model declares at all) — the long-standing silent drop (a fallback attached to no ingress is dead config) is now surfaced as a warning, not an error, since adding a matching endpoint later is a legitimate evolution path.

### Changed
- **Breaking**: the analyze output topology is rebuilt around domain slices, journey naming, and a manifest admission token. The machine-readable slice contract is `macro/{summary,finance,reliability,workloads,context-efficiency}.json` plus a `manifest.json` committed once the full slice set is on disk and before any reader — including vmr's own renderers — touches it (readers treat the snapshot as valid only if the manifest's recorded slice digests match); rendering-era facts that used to live only in Markdown (confidence markers, cost-coverage disclosure, footnotes/disclaimers, first-screen highlights) are now fields in the slices, and every timestamp carries `ts` (epoch ms) alongside `ts_display`. The monolithic aggregate JSON (`vmr-report.json`) is gone: `vmr-report.md` rebuilds from the manifest plus the slices — exactly what `-render-only` reads (summary.json carries the provenance meta, finance.json the pricing metadata), so the slices are the single persisted macro data. The `stories/` namespace is gone: `journeys/index.{json,md}` lists candidates, per-task instances live at `journeys/details/j-<id>.{json,md}` (the historical `journey-` filename prefix and the `-partial` suffix are gone; `partial` remains a JSON field + banner + index-row marker), and benchmark statistics land as `journeys/benchmarks.{json,md}`. Journey JSON is self-contained: `structure` becomes a tree over a same-file deduplicated `bodies` blob table, tool pairing upgrades from `matched bool` to three-level `match` (`exact`/`normalized`/`positional`), and truncation limits are unified at the data layer. Request detail files move to `requests/details/r-<ts>_<virt>_<real>_<outcome>_<h8>.md` with evidence at `requests/evidence/`; legacy human-readable markdown request index files are deleted — browsing is the dashboard's job, data lives in `requests/index.json`, and `requests/failed.md` remains as the triage entry. Dashboard pages are now fetch-based static skeleton HTML pages. `.parse-cache/` is now `.cache/parse/`.
- **Breaking**: `vmr report` and `vmr story` subcommand aliases are removed (`vmr analyze` is the single entry point), and the zoom flags are renamed without aliases: `-corpus` → `-benchmark`, `-story-only` → `-journey-only`.
- **Breaking**: `compare-<a>-vs-<b>.{json,md}` no longer carries a `-partial` filename suffix when either side is head-truncated (D19's suffix retirement extended to the compare family). Partiality is carried as data instead: the compare JSON's `partial` field (top level plus per-side `a_journey.partial`/`b_journey.partial`), a ⚠️ banner at the top of the `.md`, a mark in `compares/index.md`, and a per-side badge in the journey-compare dashboard page.
- **Breaking**: `role_map` and `sticky_ttl` moved from the endpoint-group (`models.<name>.endpoints[<protocol>][]`) to the provider (`providers[]`) — the role rejection `role_map` repairs is a property of a provider's API implementation (revalidated at the gateway's own enum check, e.g. DashScope rejecting the `developer` role for every model it hosts), and prompt-cache lifetime is a property of the provider's infrastructure, so both are declared once per account and inherited by every endpoint the account backs. Migration: cut `role_map: {developer: system}` / `sticky_ttl: 2h` from individual endpoint entries and place them once under the matching provider in `providers:`; strict YAML rejects the old shape as unknown fields. Load-time validation moves with the fields: provider-level `sticky_ttl` must be positive and ≤ 24h (the sticky registry's memory-eviction backstop), and `role_map` rejects blank role names, blank targets, whitespace-padded names (matching is an exact string compare, so a padded name silently never matches or rewrites to a role the gateway rejects), and self-mappings (`system: system`) — an empty map is normalized to nil. `vmr check` prints each provider's `role_map`/`sticky_ttl` in the Providers section, and endpoint rows still show the inherited values when they differ from the global default.
- **Breaking**: `soft_block_failover` configuration option (per virtual model or per endpoint) and router-level 2xx peek failover are removed. Content-flagged 2xx responses (such as MiniMax `input_sensitive`/`output_sensitive`) are passed through byte-faithfully like normal 2xx responses; `respnorm` continues to observe and record `soft_block_detected` in the audit norm trail (adjudicated in `KNOWN_ISSUES`).
- **Breaking**: `audit_retention` loses its "0 = never delete" reading — `0`/absent now means "use the default (90d)" like every other TTL field, and there is no way to spell "keep forever" anymore (write `90000d` or larger for extreme retention). A deployment that relied on the old zero-value will start deleting audit files older than 90 days at the next reload unless it sets an explicit large value.
- **Breaking**: `models.<name>.endpoints` and top-level `fallback_endpoints` are keyed by ingress protocol — `endpoints: {openai-completions: [...], anthropic-messages: [...]}` — and each entry loses its per-entry `protocol:` field (strict YAML rejects the old shape as unknown fields; no compatibility layer). Same key space as `providers[].base_url`; per-entry override fields are unchanged; within a protocol bucket, entry order still decides try-order.
- **Breaking**: endpoint-level `capabilities`/`max_context_tokens` overrides are removed — declare these facts once per real model in `model_defaults:` (or override at the virtual-model level, which remains the mechanism for "this virtual model deliberately downgrades a model it shares with others"). Migration: move an endpoint's `capabilities: [image]` into `model_defaults.<model>.capabilities` (or the virtual model's own fields); `vmr check`'s old `extra_capabilities`/own-max display lines are gone, replaced by a per-endpoint `capabilities=`/`max_context_tokens=` line whenever the endpoint's `model_defaults`-resolved value differs from what the model itself declares (or from the `"*"` wildcard baseline shared by most endpoints) — so an endpoint's actually-effective capability/context ceiling stays visible without repeating the common case on every line.
- **Breaking**: `metric: cost` quota limits are removed — `quota.limits[].metric` now accepts only `requests`/`tokens`. A control-plane budget (Limit) and a billing-plane price (pricing table) are different things that happened to be conflated: cost's only genuinely distinct behavior was a `$`-denominated trigger threshold that drifted every time the price table or exchange rate changed — the same disqualifying flaw as any control that must be "frozen at charge time" to stay meaningful. Express the same budget as a `tokens` limit instead (convert once: budget ÷ price), using `model_multipliers`/`token_weights` for per-model/per-component differences — no loss of expressiveness. `$` cost estimates remain fully available from `vmr analyze`, computed offline from raw token counts and never fed back into routing or quota decisions. A config with a `metric: cost` Limit is a load-time error naming this migration.
- **Breaking**: the top-level `pricing:` block (`currency`, `exchange_rate`, `supplement`, `standard`, `rates`, `aliases`) is removed, and pricing configuration collapses to a pure two-layer model — the built-in standard price table (unchanged, still needs no configuration) plus each account's own `providers[].pricing`, whose `map`/`overrides` fields are renamed `aliases`/`rates` for symmetry with the standard table's own naming. A `providers[].pricing.currency` is a load-time annotation only (which currency that account's `rates` rows are written in, default USD) — it is converted to USD once at load time and is never a runtime quantity: it never reaches the routing hot path, the audit log, or quota accounting. The global `exchange_rate:` map moves to the top level on its own and now has exactly two consumers, neither on the request path: normalizing a provider's non-USD `pricing.rates` into USD at load time, and `vmr analyze`'s `-currency` display conversion; an undeclared currency falls back to a new built-in default table (`standard_exchange_rate.yaml`) before erroring. External `pricing.yaml` supplement files (`pricing.supplement`/`pricing.standard`) are no longer supported — migrate their rows into the relevant provider's `pricing.rates`/`pricing.aliases`. Net effect: the routing half is now zero-price, zero-currency at runtime — pricing resolution is entirely an offline concern of `vmr analyze`.
- **Breaking**: `j-<id>.json`'s `cost.total_usd` is now `cost.total`, omitted entirely when unpriced (was `0`, which read as "this traffic was free" to any consumer that did not first check `resolved`) — and the `_usd` suffix no longer contradicts the `currency` field beside it under `-currency CNY`. `by_model[].usd` is likewise `by_model[].amount`.
- load test server-side duration instrumentation: sub-millisecond durations (0ms) from integer millisecond timestamp truncation are now preserved in distribution arrays rather than dropped via `>0` filters, eliminating upward sample bias; server-side latency percentiles in `reports/loadtest-report.md` are bucketed per load round (light/moderate/heavy) rather than blended, making per-scenario degradation observable across escalating load profiles. Generated reports are now restricted to 0600 permissions.
- console unified improvements across `/status.html`, the new `/models.html`, and `/log.html`:
  - Navigation is now four pages: **Overview / Models / Log / Help**. `/models.html` is new — it carries Quota Budgets and Virtual Models & Endpoint Topology, split out of Overview since both are relatively static configuration/topology facts that don't need Overview's fast-polling cadence. Overview keeps the vitals strip, Live Requests, Performance, Traffic & Usage, and Recent Failures. None of the four pages render a second header row (quick-link rail) any more — `mountConsole` now skips that DOM entirely when a page passes no rail entries (rather than rendering an empty row and hiding it with page-private CSS), collapsing the sticky header from 88px to 48px on all of them.
  - Upstream models across all sections now color the model name text directly using an alphabetically ordered spectrum (colored dots removed).
  - Performance by Provider & Model: removed "Mode" column and unified streaming/non-streaming into a single row per endpoint (sharing 100-entry ring in memory); rows with zero requests in the active window are hidden. The throughput column is `Tok OUT/s p50/p10` — output-token generation throughput, excluding the time-to-first-token wait for streamed requests (previously a four-component-sum-over-total-duration caliber). p10, not p90: throughput is a yield metric (bigger is better), so its worst-case tail is the bottom decile, not the top one — reusing TTFT's p90 convention here would have reported the fastest 10% of requests as a guaranteed floor. `toksOf` also floors the generation span at 50ms, dropping sub-floor samples (an upstream flushing its last chunks back-to-back can otherwise produce a physically implausible four-figure tok/s that single-handedly dominates the window). The "Tok in+cw / cr" column across this table and both Usage tables is now "Tok in (hit %)": total prompt tokens with the cache-hit share, matching the Vitals strip's existing `tok in X (hit%)` format instead of forcing readers to add fresh+cache_write and divide by hand; the fresh/cache_write/cache_read breakdown moved to the cell's tooltip.
  - Hero Panel Vitals: Requests and Tokens sections now accurately draw both today's numbers and the small total count from the durable stats ledger (matching server timezone RFC3339 day prefix), preventing zero-total discrepancies after server restarts; Tokens bottom line formatted as `tok in xx.xxM (hit%), out xx.xxM`; redundant "limit x" removed from Concurrency. The small right-hand number's label and tooltip now say which basis is actually showing — `7d` (the durable ledger's rolling window) or `since start` (process telemetry, only when the ledger has no rows yet) — instead of an unqualified `total` that read as "since the service was first deployed" regardless of which of the two very different-lifecycle sources was behind it.
  - Live Requests and the collapsible Recent Failures table (defaults collapsed, errors within 24h up to 100) live on Overview, driven by the page's existing adaptive `/stats` poller (~2s active / 15s idle) alongside the concurrency vitals — Live Requests sits right under the vitals strip, Recent Failures at the bottom of the page, below Traffic & Usage.
  - Quota Budgets (on `/models.html`): "Resets" column right-aligned and formatted as timestamps (`14:14` for today, `9-20 3:14` for future dates).
  - Virtual Models & Endpoint Topology (on `/models.html`): "Context / Capabilities" column now separates the context-size number (a `.badge` chip) from the capability tags (dim text, middot-joined) instead of one slash-joined string mixing a capacity figure with feature labels; `P0` priority (the default when `priority` is omitted, so the common case for a primary endpoint) gets its own purple badge instead of falling through to the neutral P3+ style meant for de-prioritized tiers. The `FB` fallback-tier badge uses a red style, distinct from the neutral badge shared by numeric P3+ tiers.
  - Usage section (on Overview): "Usage by Upstream Key Label" replaced with "Usage by Provider & Model", grouping rows by `Provider : Model` with matching model color; empty-provider rows from requests failed before routing render as a dedicated `(gateway / unrouted)` label; both Usage tables gain a `Tok OUT/s` column (window-average output throughput, same span rule as the Performance table's per-request `toks`) and are now full-width stacked instead of a cramped 50/50 side-by-side grid.
  - Log page (`/log.html`): back to a pure full-width terminal — the toolbar (level chips, substring filter, ⌘P pause, copy view) sits directly above the auto-wrapping log area, and the page no longer carries Live Requests or Recent Failures (those are Overview's job).
  - Configuration guides (`/help.html` + `/help.zh.html`): focused agent guides on the core supported set in designated order (Claude Code, Codex, OpenClaw, OpenCode, Cursor, Hermes, Pi Agent, WorkBuddy; other variants removed). The Quick Reference card is the page's own table of contents.
- journey `exact_repeat_tool_call` detection now requires the repeats to be locally clustered — consecutive occurrences more than 2 steps apart start a new run, so the same call scattered across a long session (a working rhythm) no longer produces a spurious "suspected loop" finding while tight interleaved loops still fire.
- `/reports/*` static hosting now follows config hot-reload: `analytics.serve` and `analytics.serve_dir` are re-read from the live routing snapshot on every request, so turning hosting on/off or repointing `serve_dir` takes effect without a restart (they were frozen at server start). With `serve` off the route answers the same bare 404 an unregistered path would.
- `vmr analyze -llm` evidence anchors must now be at least 12 runes with a letter or digit to pass verbatim-transcript verification — a model quoting only a stock token like `error` or `404` no longer yields an `[AI推测]` finding.
- audit log compression runs single-threaded (`zstd` encoder concurrency 1): a once-a-day background sweep can no longer grab every core and spike foreground request latency.
- the HTTP server now sets `IdleTimeout` (120s): an idle keep-alive connection is closed after 120s with no new request, so a client that opened a connection and vanished can't park a socket indefinitely. Applies only between requests — an in-flight request, an SSE stream, and `/log`'s long-lived stream are unaffected; `ReadTimeout` stays unset (slow request bodies are already bounded per-handler).
- console Overview page: the Live Requests table and concurrency vitals now poll adaptively on their own fast cadence (~2s while requests are in flight or queued, backing off to 15s when idle, paused cleanly while the tab is hidden), delivering a live elapsed/stalled/tokens view without coupling to whole-page 5-minute refreshes or introducing SSE complexity. `/stats` computes in-flight and concurrency fresh on every read; the ledger fold behind the rest of the payload is read-cached for longer than the poll cadence, so a burst of polls costs one aggregation. Poller requests use direct unprompted probing to avoid modal races and function out of the box on keyless instances.
- the transient cooldown curve's first step is 5s instead of 2s (still ×2 per consecutive failure, still capped at 5min — now 7 distinct steps). 2s let a recovery probe pass re-open a slow-but-alive upstream fast enough that new sessions (routed by configured order, since failover success moves the sticky pointer away) re-hit it in a tight loop, each round paying a full response_header timeout; 5s slows that flap 2.5× without making a single transient failure expensive.

## [0.6.1] - 2026-08-25
### Added
- `GET /log` + `/log.html` — the live console log streamed over HTTP as an endless `text/plain` connection: replay of the most recent ~512 lines first, then live following, replacing browser-side `tail -f`. Auth-gated via `api_keys` like `/status`; the viewer shell shares the status page's key prompt/storage and the two pages cross-link. Idle connections get a keepalive newline every 30s; slow readers skip lines with a marker instead of slowing the logging hot path
- `vmr smoke` — fire a minimal real request at every configured virtual-model × provider × upstream-model combination **through a running instance**, so the full live path applies (auth, health, conditions, quota metering, audit) and per-model quota rows become visible after a fresh config. `-provider`/`-target-model`/`-model` filter the run, `-json` for scripting; exits non-zero if any smoke failed
- Pinned routing: `X-VMR-Provider` / `X-VMR-Target-Model` headers force a request onto one specific backend within the requested virtual model's own endpoint set — defeating priority/order/quota/sticky, but strictly a narrowing lens post-filtering; the headers are consumed by the router, stripped before forwarding, and reported in `X-VMR-Route-Reason`. This is how `vmr smoke` targets each endpoint

### Fixed
- **buffered-mode truncation no longer loses data (B1)**: when an upstream connection dies mid-body on a buffered response (every non-SSE 200, plus MiniMax thinking streams), the bytes already received are flushed to the client (partial JSON for non-SSE, the streamed tail for an SSE stream already in passthrough; nothing for an SSE stream still buffered mid-`<think>`, so a dangling reasoning block can't leak) and the connection is aborted (`http.ErrAbortHandler`) — the client SDK sees a broken transfer instead of a clean, silent empty/partial 200. The audit trail already marked the attempt truncated
- **quota counters survive config reload with a default `since` (B2)**: an unset `since:` anchored the window at the exact load instant, so every startup or hot-reload recomputed the period boundary and the lazy-reset zeroed the account's accumulated usage. The default anchor is now aligned to a fixed calendar boundary (midnight for min/h/d, Monday for w, the 1st for mo), so any same-day reload keeps the count for any `every` value. A reload that crosses midnight can still shift the grid once, and only for an `every` N that doesn't divide its unit's day (`every: 5h`, `every: 7min`); set an explicit `since:` to pin those
- **LLM-inferred Findings verify their evidence anchor at runtime (B3)**: `vmr analyze`'s optional LLM interpretation layer now drops any Finding whose `EvidenceAnchor` is not a verbatim substring of the real transcript — a hallucinated anchor could previously be promoted to a HIGH-confidence `[AI推测]` Finding
- **`vmr report` Markdown escapes user-derived titles (B4)**: a session or task title containing a `|` (e.g. a quoted shell pipe) or an unclosed `<!--` no longer corrupts the table row or lets an HTML-aware renderer swallow the rest of the file — the same fix `vmr story` already carries
- hot-reload `reload()` is serialized (B5): concurrent fsnotify + SIGHUP triggers could race `rt.Install` and briefly double the effective concurrency limit
- analytics: a mid-task context compaction (stitch boundary with no new instruction) no longer opens a spurious new Task, so `len(j.Tasks)`, `plan_exec_ratio`, per-Task detectors and `-corpus` grouping stop being inflated (B9)
- incident-driven error-classification misses: vendor protocol-constraint rejections (DeepSeek thinking-mode `reasoning_content` pass-back 400; the pre-existing `thought_signature` wording moves there too) are now a new `ErrQuirk` class — switch with zero cooldown instead of dead-ending the failover walk; bai's input-token-exceeded 400 is a context-limit overflow (switch, no cooldown); a relay reporting its own OAuth refresh failure with standard error codes is `ErrAuth` (long cooldown + switch). Genuinely malformed requests keep the single-attempt `ErrClient` semantics
- quota rows' `bucket`/`gate` role is derived per model from its applicable-Limit subset — the same path routing scores with — instead of one global derivation across the provider's whole Limits list, so two same-period Limits on disjoint model scopes no longer mislabel rows
- `vmr smoke`'s probe uses `max_tokens` 4 instead of 1 — some upstreams reject ≤ 2 with a 400

### Changed
- dashboard polish: the requests summary's protocol row relabeled `By Protocol` with the full breakdown on hover; one inline-SVG favicon shared by `/status.html` and `/log.html`, nav links carrying the destination page's emoji; the quota table's ROLE column folded into badge colors (blue = bucket, red = gate, hover explains); percentages render with up to two decimals and K/M/B magnitudes drop trailing zeros
