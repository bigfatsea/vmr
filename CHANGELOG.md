# Changelog

All notable changes to this project are documented here, in
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format. This project
tags releases `vX.Y` rather than strict semver (see `internal/buildinfo`'s
doc comment for why there is no other version file to keep in sync) — the
version headers below match the tag with the leading `v` dropped.

`release.yml`'s release job extracts the section matching the pushed tag and
uses it verbatim as the GitHub Release body — GitHub's own auto-generated
notes (bare PR titles) are unreadable on this repo's mostly direct-to-main
workflow, so every tag needs a matching section here before it's pushed, or
the release job fails on purpose rather than publishing something empty.
See this file's row in `CLAUDE.md`'s Conventions section for the write-time
process (write into `[Unreleased]` as you go, retitle it when cutting a tag).

Sections before the most recent release are compressed summaries — the
commits and design docs hold the full reasoning.

## [Unreleased]

### Added
- Config validation rejects a provider whose `base_url` embeds credentials — `user:pass@` userinfo, or a credential-bearing query key (`api_key`/`token`/`secret`/…). Audit redaction only ever covered headers, so a credential written into the URL reached the audit trail and every report derived from it in cleartext. The error names the parameter, never its value; credentials belong in `api_key`, which takes `${ENV}` references
- The audit `log_dir` is locked exclusively at startup on Unix: a second vmr process pointing at the same directory refuses to start and reports the holder's pid, instead of the two silently corrupting each other's archives. No-op on Windows (no `flock`; a pidfile would outlive a crash and wedge startup permanently)
- Absolute magnitude baselines for token estimation (`internal/server`, `internal/respnorm`): fixture-backed assertions that an estimate stays in a plausible band, not just that two sides agree. A parity test is blind to both sides being wrong together, which is exactly how the inline-image estimate stayed broken
- The macro report header names the `report.yaml` a run actually applied, or says plainly that none was loaded — a config file the run never found (wrong cwd, stale `-report-config`) otherwise looks identical to a run that never had one, while self-traffic exclusion silently fails open
- `vmr.sh analyze` now auto-injects `-c config.yaml` like every other subcommand — the unified entry point was the one name missing from the wrapper's allowlist while its own deprecated aliases (`report`/`story`) were both present
- `archtest` now fails when a source-comment backtick reference `pkg.Symbol` names a symbol that no longer exists in an owned package (the dead-code shape: a comment quoting a func whose caller moved on), and enforces the one-file-per-section pairing between `internal/i18n/report_*.go` and `internal/report/section_*.go` that was previously documented but never actually checked
- `journey-*.md` Markdown report now renders a dedicated **## Behavior Indicators** (`## 行为指标`) section with the complete 17-indicator behavior profile table and an ASCII sparkline for context composition growth trajectory (start tok → end tok)
- `vmr-requests-<tag>.md` Task headers (`### tNN`) now include a one-line task summary block (turn count, total duration, fresh/cached/out token totals, and final termination status)
- `vmr-requests-failed.md` now generates an automated failure incident clustering summary (failures grouped by temporal proximity ≤ 2m, identifying the largest failure cascade and its predominant error classes)
- `vmr-report.md` §6 Sessions & Tasks table now includes a compact "Time Range" (`时间范围`) column for fast temporal navigation
- `vmr-report.md` §5 Daily Activity section now provides a folded data table fallback under the Mermaid chart for text readers and CLI viewing
- `vmr analyze -compare` Markdown report now renders a prominent **Comparison Summary** (`## 对比摘要`) card highlighting top notable differences, divergence position, endpoint identity, and termination status
- `vmr analyze -compare` System Prompt section now renders a concise unified diff (`diffLines`) between the two environments instead of duplicating ~40KB of verbatim text when prompts differ
- `vmr-report.md` Appendix now outputs client reconciliation notes when clients exist in cost/workload tables without standalone sibling files (e.g. single-shot cron traffic)
- `vmr-report.md` §0 summary table is followed by a line stating what share of total requests is `interactive` (vs heartbeat/dream_diary/compaction), so the top-line count no longer reads as all user-facing traffic (`internal/report/render_doc.go`)
- Pricing resolution now breaks bare-model-name ambiguity by vendor precedence instead of giving up: the single non-reseller row wins, and a tie among resellers still resolves to no rate. This lets models resolve directly through custom-named providers without per-model configuration. Ambiguities that precedence cannot decide (platforms reselling other vendors alongside their own line, or gateway-invented names) are pinned by aliases in `standard_price_curated.yaml` or user supplements, while `standard_price_generated.yaml` remains a pure machine price list. Chained or dangling aliases are load-time errors
- `tools/gen_standard_pricing` prints a bare-name ambiguity report after every refresh: which names collide, which are pinned by an alias, which vendor precedence picked, and which stayed unresolved. Diff two runs to see what moved across refreshes. Shares `Table`'s data and `LookupPreferredSuffix`'s rule via `Table.Ambiguities`, so the report cannot drift from runtime resolution
- `tools/gen_standard_pricing -url`: fetches the LiteLLM price list directly (default) and rewrites the checked-in snapshot with the exact bytes used, so a refresh is one command and stays reproducible. `vmr check` now warns at 60 days rather than 180 — a 20-day-old snapshot was already missing list prices for four models this repo's own traffic runs on
- `vmr analyze` / `vmr report` §2: every cost table carries a totals row, plus notes for what the total leaves out (rows whose endpoint resolved no rate), how much of it came from a degraded byte-count estimate, and how many endpoints were priced through a rate missing a component (a nil component prices as 0, so those figures are a low bound). §0's summary gains a cost column, rendering "unpriced" rather than `0` when nothing resolved
- The audit record's `Attempt` gains a `forwarded` field (JSONL schema addition, `omitempty`): the routing half stamps it at the one point a response is actually handed to the client and charged, so the analytics half no longer re-derives "this attempt served the response" from the sub-400-and-no-error-class heuristic. `IsForwarded()` is the single compatibility predicate both halves read — a stamped `true` is authoritative; on a pre-field record it falls back to that old heuristic, which a soft-block (`error_class: content`) never satisfies
- `chatmsg` counts the content-part types and usage-holder shapes it does not recognize (`UnrecognizedShapeCounts` / `ResetUnrecognizedShapeCounts`), and `vmr analyze -corpus` surfaces the snapshot as a line in the Context Rot section — a gateway dialect that silently falls through to the token-estimate path is no longer invisible
- `scripts/check-vmrsh-config-whitelist.sh` (new, run in CI's shellcheck job) fails when `vmr.sh`'s `-c config.yaml` auto-inject allowlist drifts from the set of `cmd/vmr` subcommands that actually take a `-c` flag
- Config validation rejects `:` and `/` in provider names and `api_keys` labels — either character breaks `core.EndpointLabel`'s `protocol:provider:model` three-field split, folding the provider tail into the model segment and corrupting every analysis-half grouping, detail page, and file name keyed off it
- Config validation checks virtual-model `strategy` dimension names at load time (`strategy.Build` is the authority), symmetric with pricing's load-time strictness — a typo like `["prioity"]` is caught in `vmr check`'s no-network path instead of only when `vmr start` builds the routing table
- `chatmsg.ErrorResultMarker` is an exported constant for the `❌ is_error` tool-result marker, with a test pinning `RenderPart`'s output to it; `story` referenced a private hardcoded copy that would silently desync if `chatmsg` reworded it

### Changed
- Upstream transports now enable HTTP/2 (`ForceAttemptHTTP2`): a custom `DialContext` silently disables Go's automatic h2 upgrade, so every provider connection was walking HTTP/1.1 — no multiplexing, no HPACK, and nothing anywhere recorded that fact
- Audit records now serialize with `SetEscapeHTML(false)`: bodies containing `<`, `>` or `&` (code payloads are the primary traffic) were being written as `\u003c`-style escapes, so the audit file was not the bytes the client sent and `vmr replay`'s byte-for-byte promise failed at the wire level
- `report.yaml`'s `${ENV}` expansion now rejects values starting with `#`, matching `config.yaml`'s four injection guards — the missing guard let a `#`-prefixed secret be silently truncated into a YAML comment and surface only as a mysterious 401; `report.yaml`'s currency-fallback note also moved into `i18n`
- `chatmsg` usage extraction now recognizes openai-responses' `response.completed` nesting (`response.usage`), so Responses-protocol traffic stops falling back to estimates forever; Anthropic `document` blocks (multi-MB base64 PDFs) render as a size placeholder instead of being dumped into detail pages and token counts
- Removed dead code kept alive by stale caller claims: `chatmsg.MergeUsageBytes`, `pricing.IsAggregatorVendor`, `logtee.Recent`/`Subscribe` each carried a doc comment naming a caller that had moved on or never existed
- `ctxgraph` stitch selection now pre-filters over-gap (72h) same-bucket candidates instead of letting them win on score and downgrading afterwards — a high-scoring stale match can no longer shadow a slightly-lower-scoring in-window predecessor; the strongest over-gap match survives only as the diagnostic fallback when no in-window candidate exists
- `vmr story`'s journey root-intent now reads `j.InitialInstruction` (dialect-filtered) instead of the first user-role event, which agent clients stuff with system scaffolding
- Pricing tables (`supplement` / `standard` / curated) reject NaN, ±Inf and negative rates at load time, with an error naming the offending key and rate component. A hand-written typo previously passed every check and poisoned cost accounting — the affected account's headroom score pinned at maximum, making it a traffic magnet
- `fails` in the health state machine now means "consecutive failures on the *current* backoff curve": switching between the transient (2s base) and long (10min base) curves resets the depth to 1. A run of 5xx followed by one 401 no longer jumps straight to the 1h cap
- Backoff cooldowns carry ±10% jitter so endpoints knocked out by one upstream failure stop expiring in lockstep. Jitter applies to capped values too (that is the lockstep case), so a cooldown can exceed the nominal cap by up to 10%; upstream-supplied `Retry-After` is never jittered
- A successful background probe now decays the failure depth (`fails--`) instead of zeroing it; only real traffic completing successfully resets to zero. A `max_tokens=300` probe succeeds far more readily than a 200K-token request, so treating the two as equal evidence dismantled backoff exactly for the flapping endpoints that need it
- Quota state (`vmr-quota.json`) is fsynced before the rename, so a crash or power loss can no longer surface the rename with a truncated or stale file
- Stitching evidence is stricter: overlap is a set intersection over distinct message hashes (a score can no longer exceed 1.0), and a match must clear an absolute floor of 3 shared keys *alongside* the ratio threshold. A short opening manifest cleared any ratio on a single shared message — usually the very anchor the session key was built from, which shares because it is the same conversation, not because a compaction happened
- Same-session-key stitch candidates now have a 72h upper bound; beyond it a match is downgraded to `AmbiguousMatch` rather than stitched. The old exemption ("a user can walk away for days") holds for humans but not for the recurring scheduled traffic that actually piles up under one anchor key
- Anthropic `cache_control` markers are stripped before message content hashing: moving a cache breakpoint between turns no longer reads as a content edit and fractures the lineage. Requires one cache reparse (`CacheSchemaVersion` 5→6)
- `vmr report` and `vmr story` now hand the detail renderer the same `(record, manifest, previous manifest)` triple, and the page fingerprint carries the manifest identities — the same record renders byte-identically regardless of which command ran first
- An unparseable `report.yaml` is a hard error instead of a warning that silently degrades every setting to its default. A missing file at the default path stays a silent no-op — that is "not configured", a legitimate state
- LLM-inferred findings can no longer headline a dashboard verdict. Their narrative text and evidence anchor are both influenceable by the transcript being analyzed, and the anchor check cannot distinguish a planted quote from an honest one
- Degraded token metering basis: when an upstream reports no usage, the response-side estimate is now computed over the extracted assistant text instead of raw transport bytes (SSE envelopes inflated the estimate by an order of magnitude); opaque (compressed) responses estimate 0. Routing quota charges and the analytics halves' degraded estimates share one basis, pinned by a parity test
- `/status` metrics (disk free, log/image dir sizes, memory) are served from a 30s TTL cache with runtime/metrics-based memory reads — dashboard polling no longer triggers stop-the-world pauses or recursive directory walks on the request path
- Failover classification: relays reporting exhausted balance/credit/quota as 400/403 ("insufficient balance", "余额不足", …) now fail over with a cooldown like real endpoint errors instead of surfacing as client errors; content-policy matching no longer misfires on single words that can appear in an echoed prompt ("case-sensitive"), matching phrases and structured error fields instead
- Upstream connection pooling: `MaxIdleConnsPerHost` scales with `max_concurrency` instead of being fixed at 16, eliminating connection churn above 16 concurrent streams
- One routing snapshot per request: a config hot-reload can no longer tear a single request across two config views (auth vs body limits vs routing)
- A client disconnect during streaming is no longer recorded as an upstream truncation, keeping endpoint reliability stats honest
- `journey-*.md` Findings section now groups findings by detector `FindingCode`, with hit counts, earliest step indicators, and trust-tier sorting (critical failure modes first, low-confidence detectors last) instead of flat un-scannable 100+ lists
- `journey-*.html` dashboard verdict headline gracefully degrades to "secondary signal only" (`仅次级信号`) when only low-confidence detectors fired, avoiding misleading confident verdicts on unconfirmed signals
- `journey-*.html` metrics grid renders `n/a` for Error Recovery Count when running on non-Anthropic Messages protocols where error recovery is structurally undetectable, avoiding misleading `0` counts
- `Step` model in `internal/story` now captures request `Outcome` and `ErrorClass`, enabling the decision spine to correctly flag failed steps (`🔷 ⚠️`) and overview cards to report request-level HTTP/upstream failures
- `vmr-report.md` §3 Reliability and §4 Latency endpoint tables now fold low-sample endpoints (`Attempts < 20` or `Requests < 20`) into `<details><summary>+ N more low-sample endpoints</summary>`, keeping main tables focused on production endpoints
- `internal/reqdetail` JSON indentation now disables HTML escaping (`SetEscapeHTML(false)`), preserving clean literal `<, >, &` and unescaped newlines in tool call arguments
- `vmr analyze -corpus` Spearman correlation table now filters out known definitionally mechanical identities (e.g. `NetWorkingMS` vs `ModelMS`, `ToolCallCount` vs `ContextUtilization`), elevating empirical correlations

### Fixed
- `respnorm.stream.opaque` writes are mutex-guarded: the overflow-degradation flag was written unlocked while `OutTokens()` read it under lock — a data race reachable on >8MB runaway streams, now covered by a dedicated `-race` test that reproduces the race on the unfixed code
- `tokenutil`'s regression coefficients now document their provenance honestly (fitting corpus/tokenizer no longer recoverable) and the recalibration path, instead of presenting six bare numbers as if derived
- Responses tool pairing & results: `CheckToolPairing` and `ToolResultList` now decode OpenAI Responses flat `function_call` and `function_call_output` items, enabling story finding detectors (`ToolErrorRecovery`, `UnusedToolResult`, etc.) on Responses traffic (`internal/chatmsg/pairing.go`, `internal/chatmsg/toolresults.go`)
- Token estimation semantics: `EstimateRequestBodyTokens` is separated from response-body estimation, eliminating redundant JSON response unmarshaling attempts on request bodies and reinforcing degraded basis safety boundaries (`internal/chatmsg/usage.go`, `internal/chatmsg/tokenest.go`)
- Entity spans extraction: `collectEntitySpans` is optimized to $O(N \log N)$ interval filtering, eliminating $O(N^2)$ comparison overhead on large tool outputs (`internal/chatmsg/entities.go`)
- Replay concurrency safety & protocol parity: `vmr replay` detects active router locks via `audit.DirLockOccupier` and operates in in-memory mode without overwriting online daemon quota state, and passes ingress protocol to `chatmsg.MergeUsageWithProtocol` (`internal/replay/replay.go`)
- Audit housekeeping: expired audit log files are now purged directly instead of wasting CPU and disk IO compressing them before deletion (`internal/audit/housekeep.go`)
- Image cache sweep: orphaned `.tmp-` files older than 1 hour are pruned during cache maintenance regardless of whether TTL expiry is enabled (`cache_ttl_days: 0`), preventing disk leakage (`internal/imgprep/cache.go`)
- Single-source token usage extraction: offline analytics (`report`, `ctxgraph`, `reqdetail`) now consistently pass the record's ingress protocol to `chatmsg.ExtractUsageWithProtocol`, aligning offline token accounting with online router metering under non-standard gateways (`internal/report`, `internal/ctxgraph`, `internal/reqdetail`)
- Quota accounting: `ApplyModelMultiplier` preserves the `Cost` counter without unintended field zeroing (`internal/quota/weight.go`)
- Pricing validation: `Rate.MissingComponents()` now identifies non-finite (`NaN`, `±Inf`) and negative rates, matching `Complete()`'s validation criteria (`internal/pricing/pricing.go`)
- Error classification: `errorSnippet` trims leading whitespace and newlines before checking JSON structure, preventing non-standard proxy gateway errors from unnecessarily falling back to raw-text snippet scanning (`internal/adapter/classify.go`)
- Image downscale geometry: `scaledSize` adds defensive guards against non-positive dimensions and max bounds to prevent integer division panics on malformed images (`internal/imgprep/imgprep.go`)
- OpenClaw dialect parsing: leading scaffolding brackets (`[message_id: ...]`, `[timestamp]`) are now stripped from user messages following `(untrusted metadata)` envelope removal, preventing task title and intent corruption (`internal/taskseg/openclaw.go`)

- a missing `api_key` or an unset/empty `${ENV_VAR}` the config referenced now raises a boxed `CONFIG PROBLEMS` banner on start/reload (naming the unset vars), instead of one quiet `WARN config check:` line that drowns in the config dump. Purely advisory issues still log a single WARN line
- a request for a virtual model whose endpoints are **all** keyless now gets an immediate `vmr_no_api_key` 503 naming the model, instead of a raw upstream 401 (often provider/CDN HTML) plus a 10-minute health cooldown per endpoint
- `vmr check` now warns when a `metric: tokens`/`cost` quota account backs an `openai-completions` endpoint: a streaming response has no usage block unless the client sent `stream_options.include_usage:true` (which vmr won't inject), so quota accounting falls back to a byte estimate. `vmr status` and `vmr report`'s quota rows add the same explanation when `estimated_pct` is ≥95%
- `vmr analyze` peak memory: the stitch blob-lineage inverted index switched from one `map[int]bool` per message hash to a `[]int` posting list, removing millions of tiny-map headers from a large-corpus run

### Fixed
- `soft_block_failover`: an upstream that broke mid-transfer (or tripped the `stream_idle` watchdog) while `checkSoftBlock` was pre-reading the 2xx body had that read error silently swallowed, and the truncated fragment was forwarded to the client as a clean `200 OK`. The peek now surfaces the error so the client connection aborts — the same broken-transfer signal the normal streaming path already gives
- release tarball was missing `config.minimal.yaml` / `config.minimal.zh.yaml` (the file README Quick Start tells you to copy) and `vmr.sh` (the dev/service supervisor README documents); all three are now packaged
- `vmr analyze` default suite (no `-journey`, no `-render-all`) no longer writes journey reports with dead `../details/` / `../evidence/` links: since that path deliberately does not materialize the detail/evidence pages (volume discipline), the decision spine and system-prompt header now render an inline `file:line` coordinate instead of a Markdown link. Zoom into one journey with `vmr analyze -journey <id>` for the fully linked report (unchanged). `vmr analyze -compare` naming a journey the default suite already wrote now re-renders it with real links rather than leaving it on coordinates
- `/help.html` guide section width mismatch: a stray `</div>` prematurely closed the `.container`, rendering guide cards at full viewport width instead of matching the 960px connection card above it
- `/help.html` auth modal was rendered open on first load — the stylesheet was missing the `.hidden { display: none !important; }` rule the modal (and its error line) rely on, so the "Authentication Required" dialog sat over the page whether or not the instance requires a key. The modal now starts hidden and only opens on a real `/status` 401 (or a click on the reveal link)

## [0.6.1] - 2026-08-25
### Added
- `GET /log` + `/log.html` — the live console log streamed over HTTP as an endless `text/plain` connection: replay of the most recent ~512 lines first, then live following, replacing browser-side `tail -f`. Auth-gated via `api_keys` like `/status`; the viewer shell shares the status page's key prompt/storage and the two pages cross-link. Idle connections get a keepalive newline every 30s; slow readers skip lines with a marker instead of slowing the logging hot path
- `vmr smoke` — fire a minimal real request at every configured virtual-model × provider × upstream-model combination **through a running instance**, so the full live path applies (auth, health, conditions, quota metering, audit) and per-model quota rows become visible after a fresh config. `-provider`/`-target-model`/`-model` filter the run, `-json` for scripting; exits non-zero if any smoke failed
- Pinned routing: `X-VMR-Provider` / `X-VMR-Target-Model` headers force a request onto one specific backend within the requested virtual model's own endpoint set — defeating priority/order/quota/sticky, but strictly a narrowing lens post-filtering; the headers are consumed by the router, stripped before forwarding, and reported in `X-VMR-Route-Reason`. This is how `vmr smoke` targets each endpoint

### Fixed
- **buffered-mode truncation no longer loses data (B1)**: when an upstream connection dies mid-body on a buffered response (every non-SSE 200, plus MiniMax thinking streams), the bytes already received are flushed to the client (partial JSON for non-SSE, the streamed tail for an SSE stream already in passthrough; nothing for an SSE stream still buffered mid-`<think>`, so a dangling reasoning block can't leak) and the connection is aborted (`http.ErrAbortHandler`) — the client SDK sees a broken transfer instead of a clean, silent empty/partial 200. The audit trail already marked the attempt truncated
- **quota counters survive config reload with a default `since` (B2)**: an unset `since:` anchored the window at the exact load instant, so every startup or hot-reload recomputed the period boundary and the lazy-reset zeroed the account's accumulated usage. The default anchor is now aligned to a fixed calendar boundary (midnight for min/h/d, Monday for w, the 1st for mo), so any same-day reload keeps the count for any `every` value. A reload that crosses midnight can still shift the grid once, and only for an `every` N that doesn't divide its unit's day (`every: 5h`, `every: 7min`); set an explicit `since:` to pin those
- **LLM-inferred Findings verify their evidence anchor at runtime (B3)**: `vmr analyze`'s optional LLM interpretation layer now drops any Finding whose `EvidenceAnchor` is not a verbatim substring of the real transcript — a hallucinated anchor could previously be promoted to a HIGH-confidence `[AI推测]` Finding
- **`vmr report` Markdown escapes user-derived titles (B4)**: a session or task title containing a `|` (e.g. a quoted shell pipe) or an unclosed `<!--` no longer corrupts the table row or lets an HTML-aware renderer swallow the rest of the file — the same fix `vmr story` already carries
- hot-reload `reload()` is serialized (B5): concurrent fsnotify + SIGHUP triggers could race `rt.Install` and briefly double the effective concurrency limit
- analytics: a mid-task context compaction (stitch boundary with no new instruction) no longer opens a spurious new Task, so `len(j.Tasks)`, `plan_exec_ratio`, per-Task detectors and `-corpus` grouping stop being inflated (B9)
- incident-driven error-classification misses: vendor protocol-constraint rejections (DeepSeek thinking-mode `reasoning_content` pass-back 400; the pre-existing `thought_signature` wording moves there too) are now a new `ErrQuirk` class — switch with zero cooldown instead of dead-ending the failover walk; bai's input-token-exceeded 400 is a context-limit overflow (switch, no cooldown); a relay reporting its own OAuth refresh failure with standard error codes is `ErrAuth` (long cooldown + switch). Genuinely malformed requests keep the single-attempt `ErrClient` semantics
- quota rows' `bucket`/`gate` role is derived per model from its applicable-Limit subset — the same path routing scores with — instead of one global derivation across the provider's whole Limits list, so two same-period Limits on disjoint model scopes no longer mislabel rows
- `vmr smoke`'s probe uses `max_tokens` 4 instead of 1 — some upstreams reject ≤ 2 with a 400

### Changed
- dashboard polish: the requests summary's protocol row relabeled `By Protocol` with the full breakdown on hover; one inline-SVG favicon shared by `/status.html` and `/log.html`, nav links carrying the destination page's emoji; the quota table's ROLE column folded into badge colors (blue = bucket, red = gate, hover explains); percentages render with up to two decimals and K/M/B magnitudes drop trailing zeros

## [0.6] - 2026-08-23
### Added
- Quota-Aware Routing P3: multiple windows per provider (e.g. an RPM gate beside a monthly bucket), merged bucket-vs-gate — the longest-period Limit is the bucket (underuse boosts the score), shorter gates cap at neutral; `every: min` units and bare clock-time `since` for min/h Limits; a Limit's `models:` scope selects both which models it applies to and whether they share one pool or get independent ones (`"*"` is a reserved token, not a glob)
- exact fractional-multiplier charging: `model_multipliers` charge the configured value instead of silently rounding each charge up (quota counters went float64; a one-directional `vmr-quota.json` upgrade)
- config ergonomics: labeled `api_keys:` expands one provider entry into independent per-account providers at load time; `endpoints[].providers` packs several accounts into one try-order entry; top-level `fallback_endpoints:` appends tail fallbacks to every qualifying virtual model
- `vmr analyze`: single entry point for the whole analytics suite; `vmr report`/`vmr story` became thin aliases routed through its dispatch (breaking); six zoom modes (`-journey`/`-compare`/`-corpus`, `-macro-only`/`-list-only`/`-story-only`)
- story depth: Phase 1b LLM semantic detectors (six behavioral-defect Findings anchored to verbatim transcript evidence), Context Rot and Tool Sequence Pattern corpus sections, output-repetition-rate metric, per-Journey model-usage & switches table, a machine-readable `structure` skeleton in `journey-<id>.json`, per-Step "→ detail" links rendered on demand
- stable record coordinates: a `req` field joining `vmr-report.json` and `vmr-stories.json`, `vmr replay -req COORD` and `-print`, `internal/audit.LineAt`; the redundant per-detail-page `.json` copies were removed with them
- shared `internal/reqdetail`: detail filenames derive from the record's own coordinate hash (byte-identical across runs and machines); system prompts and tool sets deduplicated into content-addressed evidence blobs
- parse cache: its own `{out}/.parse-cache/<hash>` shards stamped with a schema version, extended to cover report's aggregation facts — warm full-corpus rerun dropped ~72s → ~16s
- `GET /health`: unauthenticated liveness-only endpoint (`{status, time, uptime_seconds}` + no-store) — deliberately never readiness
- `GET /status.html`: single-page CSR dashboard (auto-refresh, health/cooldown badges, concurrency/system/traffic gauges, quota bars, key prompt modal), embedded via `//go:embed`, zero CDN dependencies
- self-traffic exclusion: analytics exclude the instance's own `-llm-addr` interpretation calls from cost/usage totals by default
- the strategy design doc (`docs/VirtualModelRouter_Design_v4_Strategy.md`) and an archtest documentation-drift guard over every cited path/package/symbol

### Changed
- **Breaking**: `/admin/status` → `/status`, loopback-only restriction dropped, auth unified under `api_keys`; `vmr status` reads the key from config
- **Breaking**: `/status` payload restructured into `instance` / `system` / `traffic` blocks (config sub-object, lock-free atomic traffic/token counters)
- **Breaking**: report `sessions[].id` switched from positional `s01` labels to content-addressed lineage ids, directly joinable against story journeys
- the default analyze suite renders cron/subagent journeys too (only heartbeat stays collapsed); large-batch rendering builds in chunks of 20, bounding peak memory
- detail pages slimmed: raw SSE bodies replaced by a `vmr replay -print -req` pointer, previous-turn history folds into a link, default runs materialize no `details/*.md` (one real day: 47MB → 3MB; `-render-all` pages shrank ~86%)
- response normalization extracted into `internal/respnorm` with `io.Reader`-level fuzz coverage (no behavior change); `jsonscan` scanners hardened against out-of-range indices; the client-header blocklist and JSON/error writers moved from `core` to `router`
- session/task segmentation unified into `internal/taskseg` (report and story were two independently-maintained copies); four drifting token formatters converged on `fmtutil`

### Fixed
- streams aborted by client disconnect audit as `canceled` and no longer trip upstream health penalties
- respnorm: infinite read-after-EOF loop for generic `io.Reader` consumers; spurious extra `[DONE]`/blank line under TCP fragmentation
- report↔router parity: degraded token/cost estimates reproduced instead of silently rendering 0/`-` (estimated share shown), window consumption computed on forwarded attempts, same-account multi-key double counting
