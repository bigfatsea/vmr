# Virtual Model Router (vmr) — 设计方案 · 进行中请求（Live）

**这是 v4 版设计文档里路由半区的一个子系统专篇。** 它描述控制台「现在正在发生什么」这一半：In-flight 注册表、已结束环、`GET /status/live` 契约，以及 Overview 上 Live Requests 表的呈现与刷新方式。「过去发生了什么」——请求统计、查询引擎与统计页——见 Stats 设计文档。

配套文档：
- Part 1（Core）—— 请求生命周期与并发闸是本文的邻接面。
- Stats 设计文档 —— 完成后的请求作为事件进入统计模块，与本文的运行时状态互不交叉。

---

## 1. 问题与约束

运营者需要实时看到：当前有几个请求在排队、几个在执行、各自已耗时多久、打到了哪个端点、是否已经 failover、流式响应是否卡住、已经产出了多少 token。

1. **热路径零阻塞**：进行中盖章只用无锁原子更新或局部快照，不在请求路径上做任何聚合。
2. **纯内存、零落盘**：进行中状态是瞬态的，进程重启即清空；需要持久化的「请求最终是什么样」由统计模块负责。
3. **隐私分级**：只有定量信息与端点标识，不含正文。

## 2. 两本账的划分

| | 进行中（本文） | 已完成（Stats 设计文档） |
| --- | --- | --- |
| 回答 | 现在正在发生什么 | 过去发生了什么 |
| 归属 | `router` 的 In-flight 注册表 | `internal/stats` 的事件存储 |
| 生命周期 | 请求进入并发闸前登记，退出主流程时移除 | 收尾钩子记账一次，永久保留 |
| HTTP | `GET /status/live` | `GET /stats/*` |

请求的排队、逐次尝试、流式逐块盖章都发生在 router 内部，早于任何审计记录产生；完成时钩子对每个请求恰好记账一次。两条路径互不写对方的数据。

## 3. In-flight 注册表

- **注册时机**：完成协议预检与鉴权之后、进入并发闸之前注册，初始状态 `queued`。未获得协议与虚拟模型名之前的请求无法归属，慢速上传请求体也不占并发槽，所以 body 上传与预检阶段对注册表不可见。
- **出站盖章**：向上游发起尝试时转为 `running`，记录发出时间与目标端点；failover 时覆盖为新的尝试序号与端点。
- **流式跟踪**：首个数据块到达时盖章首字节时刻；每个数据块到达都刷新末块时刻与累计输出 token 估计。逐块盖章、刻意不节流——末块时刻用于卡死检测，攒批会让一个已卡死的流显得「更新鲜」。
- **注销**：请求退出主流程（成功、失败、取消或中途断开）时整条移除，同时把终态快照（`state: "ended"`、`ended_at`）推入容量 32 的已结束环。已结束环是纯呈现数据，不落盘，进程重启清空。

## 4. `GET /status/live` 契约

鉴权与其他管理接口相同。

| 字段 | 内容 |
| --- | --- |
| `concurrency` | 全局并发闸：`limit`、`in_flight`、`waiting` |
| `providers_concurrency` | 按 provider 的并发闸水位（配置了 provider 级并发上限时出现） |
| `inflight[]` | 进行中请求：序号、状态、到达时间、发出时间、尝试序号、端点、首字节与末块时刻、输入 / 输出 token 估计 |
| `recently_ended[]` | 已结束环，按序号降序，元素结构与 `inflight` 相同并附 `state: "ended"` 与 `ended_at`；空时为 `[]` |

响应只含运行时状态，忙时每秒一次的轮询代价就是一次小快照。

## 5. 呈现：Slot 列表与数字动效

实时感的瓶颈不在数据管道而在呈现——「行随请求结束突然消失」与「Token 数瞬间跳变」是仅有的两个体验痛点，解决它们的工作放在前端：

- **Slot 列表**：Live Requests 表维持固定行数（`clamp(concurrency.limit + 2, 8, 12)`）的持久行（序号 → 行）。每次轮询把 `inflight[]` 与 `recently_ended[]` 按序号归并：新请求插入顶部；出现在已结束环里的行打 ended 徽标并冻结全部数值（终值来自后端终态快照）；超出槽位从底部移除；连续两次轮询都消失的行也按 ended 冻结（前端兜底）。表格上方以徽标提示排队数。
- **指标带是常驻的实时视图，Slot 表是按需的抽屉。** 指标带三格各司其职、互不重复：**In flight**（运行数 / 并发上限，每个槽位一个小方块，排队数）、**Endpoints**（健康）、**Live requests**（每个进行中的请求一行：序号、调用方 → 虚拟模型、已耗时；卡住的流式请求排最前并带红色 stalled 徽标，排队与故障转移各有标记；超过三行时显示「+N more」；空闲时是 Idle 加最近一条结束请求的调用方、模型、耗时与结束时间）。这一格固定预留三行，请求的开始与结束都不会让下面的内容移动。完整的 Slot 表在「table」按钮后面，**从不自己展开**，用户的开合选择记在浏览器里（`localStorage`，读写失败就当作收起）。表格收起时 Slot 状态照常归并，展开时看到的就是当前槽位。
  - 为什么不自动展开：忙碌的 Agent 会让路由器几乎一直有请求在跑，自动展开的表格（8–12 行）把整个统计仪表盘永久压到首屏之下，而且每次一阵请求结束又把页面整体上移——读图、点选时页面在手底下跳。卡住与排队这两类需要注意的状态已经在指标带的行里直接可见，不需要靠展开一张表来提醒。
  - 为什么合并并发与摘要：此前同一个事实出现三处——并发格的 `0 / 6`、摘要格的「N running · M queued」、表格头部的徽标。现在数字只在 In flight 一处，摘要格只回答「是哪些请求」。版本号、pid 与监听地址已经在页脚、uptime 在页头，资源行只留内存、磁盘与开关。
- **数字动效**：`console.js` 的 `VMRTween.number` 提供 500 ms ease-out 数字过渡，接入 token 估计列；Elapsed 列不做动效，也不做本地计时——轮询到多少显示多少。
- **卡死提示**：流式请求的末块超过 5 秒未刷新时，TTFT 列显示 stalled 徽标。

## 6. 刷新方式：自适应短轮询

**结论：保留自适应短轮询（忙时 1 秒、闲时 15 秒、页面隐藏时暂停），不用 SSE 或 WebSocket。**

| 方案 | 评估 |
| --- | --- |
| SSE（EventSource） | 浏览器的 `EventSource` 不能设置 `Authorization` 请求头，只能把 key 放进 URL 或改用 cookie。前者违反「key 不进 URL、不进服务端日志」的既有约定，后者要新建一套会话机制。用 `fetch` 流式读取可以带请求头（`/log` 就是这样做的），但仍需断线重连与状态恢复 |
| WebSocket | 同样不能设置请求头，还要多一套连接与心跳管理 |
| 自适应短轮询 | 普通 `fetch`，天然沿用现有鉴权；进行中请求是「状态快照」而不是事件流，全量快照轮询天然幂等、断线自愈 |

轮询自身不弹鉴权框、不提示错误：整页 5 分钟刷新负责鉴权与错误提示，轮询失败只是静默退回闲时节奏。

## 7. 决策与不变量

| 决策项 | 设计选择 | 权衡依据 |
| --- | --- | --- |
| **进行中与已完成分账** | In-flight 注册表永不落盘、不结算；完成后的请求进入统计模块 | 两种问题、两种生命周期，混在一起只会让两边都变复杂 |
| **已结束环独立平面** | 终态快照走 `recently_ended[]`，不混入 `inflight[]` | `inflight` 只含进行中请求的语义不动摇；前端冻结的是后端的权威终值 |
| **独立的 `/status/live`** | live 轮询只取运行时状态 | 统计数据分钟级刷新即可，不必搭每秒一次的轮询的车 |
| **呈现层吸收实时性** | Slot 持久行 + 数字动效，节拍维持 1 秒 | 行消失与数字跳变两个真实痛点已在呈现层解决，剩余 1 秒粒度在 slot 模型下无感知 |
| **动效依赖持久 DOM** | Live 表按序号复用行，不整表重建 | 数字过渡需要跨轮询的元素记忆；顺带消除整表重建的闪烁与选区丢失 |
| **轮询而非推送** | 见「刷新方式」 | 推送在请求头鉴权下没有简单的实现，而全量快照轮询天然自愈 |
| **「此刻」与统计是两个故障域** | 统计不可用（存储打不开、查询报错）只影响仪表盘区域：它自己显示原因与重试，并发、端点健康、告警、系统行与 Live Requests 照常渲染 | 出问题的时候（磁盘满、`log_dir` 权限错）恰恰是最需要「此刻」那一半的时候；数据层已经把两者分开，渲染层不该再把它们绑进同一个失败路径。由 Node 渲染测试（统计后端 503）锁定 |
